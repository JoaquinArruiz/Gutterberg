# M12 — Sheet engine (Rust only)

**Goal:** `card-core` can build output sheets from any list of cards and quantities, with
full tests and no UI changes. This is the engine for the Print stage (M13); see
`README.md` in this folder for the direction.

## Scope

- `extract_cards(document_id, pages: &[PageSize], groups) -> Vec<Card>`, with
  `Card { id: CardId, source: OrientedRect, scale: f64 }` (`CardId` and `OrientedRect`
  from M11). Grid cards come from the existing `SourceCard` generator in `layout.rs`, with
  angle 0 and scale 1.0. Freeform groups (M18) map one-to-one.
- **Card transform.** Each card has an explicit `scale` (default 1.0, set only by the user
  in M18) and gets an output `turn` of 0, 90, 180 or 270 degrees (default 0). Its final
  size is `source size × scale`, with width and height swapped for 90 and 270. Layout,
  size grouping and overflow all use this final size.
- `SheetSpec { page: PageSize | Fit, rows: Option<usize>, columns: Option<usize>,
  gap_x_mm, gap_y_mm, margins }`. `None` for rows/columns = as many as fit on the page.
- `paginate(cards: &[(Card, quantity)], spec, options) -> Result<Vec<OutputSheet>>`, with
  `OutputSheet { page: PageSize, placements: Vec<SheetPlacement> }` and
  `SheetPlacement { card_id, source: OrientedRect, destination: Rect, turn, scale }`.
  `destination` is the upright slot on the sheet. No automatic scaling: a card that
  doesn't fit the page is an error, never shrunk.
  - **Quantities:** any quantity per card, e.g. 4 × A, 2 × B, 3 × C.
  - **Order** (`options.order`): `Grouped` gives A A A A B B C C C; `Interleaved` goes
    round-robin until each card runs out: A B C A B C A C A.
  - **Mixed sizes** (`options.group_by_size`, default `true`): split the cards into one
    group per final size (after turn and scale; sizes within 0.5 mm count as equal), and give each group its own
    sheets with a grid that fits that size. Order applies within each group. With
    `false`, all sizes share one grid: slot size = the largest card, smaller cards centred
    in their slot.
- `export_sheets(sources, &[OutputSheet])`: generalise `export_document`. Sources can be
  several PDFs (keyed by `document_id`): import each document's objects into the output
  once (renumbering object ids), wrap each source page as a form once, and list one form
  per distinct source page in each output page's resources (`/S{doc}_{page}`). Only the
  single-document path is used by the UI until M14, but test the multi-document path now.
  - **Placing a card:** clip to the source `OrientedRect` (a rotated rectangle path, not
    `re`), then one `cm` matrix that undoes the source angle, applies the output turn and
    the scale, and moves the card into its slot. Still vector; nothing is rasterised.
    Factor the matrix maths into a pure, unit-tested function.
- Rebuild today's behaviour on top of it: "all cards in order, sheet grid = source grid"
  must produce the same placements as the current `calculate_layout` path (property test
  over random grids). Then make `export_document` a thin wrapper, so there is one export
  path.
- A `compute_sheets` Tauri command for the preview (not wired into the UI yet).

## Done when

Tests cover:

- 9 × one card on a 3×3 A4 sheet;
- 3 cards × 3 each on one sheet;
- a quantity that spills onto a second sheet;
- both orders with unequal quantities (4 × A, 2 × B, 3 × C);
- mixed sizes with `group_by_size` on (separate sheets) and off (shared grid, centred);
- cards from two source documents on one sheet;
- a source card rotated 7°, with an output turn of 90° and a scale of 0.97: check the
  final size, and that its centre and corners land where expected in the output;
- the equivalence property with the current layout path.
