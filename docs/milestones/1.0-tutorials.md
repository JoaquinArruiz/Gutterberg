# 1.0.0 — Tutorials

Most of what people ask about Gutterberg it already does: resizing pieces, lining up the backs, gutterfold, pairing
backs, paper size (see the r/printandplay thread, October 2026). Help tips show once, at a moment the app picks, and
then they are gone. A tutorial is the same kind of guided walkthrough, but started by the user when they need it:
"show me how to make these cards bigger".

## Goal

A **Tutorials** list the user can open at any time. Picking one starts a short walkthrough that points at the real
controls (spotlight and Back / Next, as the help tips do today) and moves on when the user does the step.

## Words

Add **tutorial** / **tutorial** to the glossary in `AGENTS.md`: "A walkthrough of one task that the user starts from
the Tutorials list; unlike a help tip, it is never shown on its own." A tutorial step looks like a help tip, but it is
not one.

## How it works

- **One step format.** A tutorial's steps are `HintStep`s (`src/lib/hints.ts`): text, target, `tipAt`, placement,
  `advanceOn`, action. Draw them with the same `HintCard` and Joyride code as `HintToast`. Pull that code out of
  `HintToast.tsx` into a shared piece instead of copying it.
- **Its own catalog.** `src/lib/tutorials.ts`, with an id, a title, a one-line summary, a group (Source, Print,
  Duplex, App), what it needs before it starts, and its steps. Texts go under `tutorials.<id>.…` in both locales.
- **What it needs.** `needs: "nothing" | "document" | "pieces"`. When the need isn't met, the first step says so and
  offers the way there (Open PDF…, or "Mark some pieces first" that starts the first tutorial). A tutorial never
  loads a sample PDF or changes the user's project by itself.
- **Getting to the right place.** A step can have an `action` that brings the user to where the step happens (switch
  to the Print tab, open the Duplex panel, open Preferences at a setting). Add these to `hint-actions.ts`. The
  existing `open-preferences:*` pattern already does this for Preferences.
- **Starting one ignores the tip settings.** `help.tipsOn` and dismissed tips don't apply, since the user asked for
  it. While a tutorial runs, no help tip shows (the same hold as the welcome tour, `hintsHeld`), and the tutorial
  ends with Done, the ×, or Escape.
- **One host.** `ui-store` gets `tutorial: { id, step } | null`. A `TutorialHost` mounted once in the app renders
  it. When a step's target isn't on screen, it shows as a toast at the bottom centre, as `HintToast` does.
- **Nothing is saved.** No preference or project change, so 1.0.0 stays on the same project and preferences
  versions. The list doesn't track which tutorials were finished.

## Where the list is

1. **A Help menu in the toolbar** (a `?` button next to Preferences, there with or without a PDF open). It has
   Tutorials…, Keyboard shortcuts, Welcome tour and Report a problem, and it puts in one place what is spread out
   today.
2. **Preferences › Help › Tutorials**, the same list above the tips switch.

The list is a small dialog grouped by tab, with a search field like the shortcuts sheet's (by the translated title
and summary, ignoring case and accents). Picking a tutorial closes the dialog and Preferences, then starts it.

## The first tutorials

From the thread, in this order. Each one is 2 to 5 steps. New `data-hint-target`s are needed where the target
doesn't exist yet (Selected piece size and Scale, the Duplex panel, back offset, Pair backs automatically…, the sheet
size, the references button, the Grid tool, Preferences › Updates).

| Id | Title | Needs | Steps (short) |
| --- | --- | --- | --- |
| `resize-pieces` | Make pieces bigger or smaller | pieces | Print tab → pick a piece in the library → Selected piece: type the size in mm (the other side follows) or the Scale → the sheet shows it |
| `align-backs` | Line up fronts and backs | pieces | Print › Duplex → Calibration sheet… → print it, read the two numbers → Back offset X/Y |
| `gutterfold` | Print gutterfold, or turn it into double-sided | pieces | Duplex › Backs › Beside the front → fold or Cut apart → pairing turns gutterfold into double-sided |
| `pair-backs` | Pair fronts with their backs | pieces | Piece library › Pair backs automatically… → Alternating pages or Backs in another PDF → check the pairs |
| `paper-size` | Choose the paper size | document | Print tab → Sheet size (A4, Letter, A3…) → orientation |
| `find-piece` | Find a piece on the sheet | pieces | Sheet preview → Show piece references → the same reference in the library |
| `several-grids` | Mark pieces of different sizes on one page | document | Grid tool → draw the second grid → name and colour → the Select tool picks either |
| `images-as-pieces` | Use images as pieces | nothing | Open images → size dialog → they join the library |
| `mark-and-export` | Mark pieces and export | document | The first-PDF tour's steps, so it can be run again |
| `update` | Update Gutterberg | nothing | Preferences › Updates → Check for updates → Install |
| `report-problem` | Report a problem | nothing | Help menu › Report a problem → Copy log → the GitHub form |

`mark-and-export` reuses the step list of `first-pdf-tour` and `print-stage-intro`, so it isn't written twice.

## Steps

1. Pull the card and Joyride code out of `HintToast` so a tutorial and a tip draw the same way.
2. The catalog, the store state and `TutorialHost`, with the needs check and Escape.
3. The Help menu and the Tutorials dialog, plus Preferences › Help › Tutorials.
4. The tutorials in the table, with their targets, events and actions, in English and Spanish.
5. Tests: the catalog and both locales have the same keys (as `hints.test.ts` does), each tutorial's targets and
   events exist, a tutorial runs with tips off, no tip shows during one, and the needs step shows without a PDF.
6. Check the dialog and every tutorial at 900 × 560, in both themes and both languages.
7. Docs: `docs/architecture.md` (Help), `docs/controls.md`, `CHANGELOG.md`.

## Out of scope

- Videos or clips in tutorials (the welcome tour has them, but tutorials don't).
- A sample project that tutorials open by themselves.
- Tracking which tutorials were done, and suggesting one at the right moment (that is what help tips are for).
- Links from outside the app that open a tutorial (for example from a Reddit answer).

## Done when

Every tutorial in the table runs to the end in both languages on a real project, a tutorial works with help tips
turned off, and every check in `AGENTS.md` passes.
