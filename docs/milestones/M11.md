# M11 — Document model

**Goal:** each page can have its own grid or be skipped, and export checks every page
before asking where to save.

Today one grid is applied to every page (`src-tauri/src/commands/export.rs` builds
`(0..page_count)` with the same `GridLayout`), and overflow is only checked on the current
page. Rulebook and card-back pages get cut into cards, and another page can fail mid-export.

## Scope

- **Model.** Replace the single grid in `src/stores/layout-store.ts` with a
  `DocumentLayout`: a list of page groups, each either `{ pages: range, grid, selection }`
  or `{ pages: range, skip: true }`. Default: one group covering all pages. Output settings
  (gap, page size, margins) stay global for now; they move to the Print stage in M13.
- **Pages panel** (`src/components/sidebar/PagesPanel.tsx`): an include/skip toggle per
  thumbnail, and "Apply this grid to…" (this page / a range / all pages of the same size).
  A badge on thumbnails whose page belongs to a different group.
- **Export.** `export_document` takes a list of `PageJob`s built from the groups
  (`ExportJob` already supports one grid per page). Remove `page_count` from the IPC.
- **Pre-flight.** A new `validate_export` command runs `calculate_layout` for every
  included page and returns per-page errors. The toolbar lists them and blocks export
  before the save dialog opens.
- **Undo/redo** for selection, grid and group edits. `zundo` (Zustand temporal middleware)
  is the cheap option; group rapid drags into one step. Bind Ctrl/Cmd+Z and
  Shift+Ctrl/Cmd+Z.
- **Card identity.** Define `CardId` in Rust (`card-core`) and TypeScript now; M12 builds
  on it. Two kinds:
  - `Grid { document_id, page_index, row, column }` for cards from a grid group;
  - `Freeform { document_id, page_index, index }` for cards drawn one by one (M18). Define
    the variant now; nothing creates it yet.

  Only one document is open in this milestone (use a fixed `document_id`), but sheets will
  later mix cards from several PDFs (M14), so the id must carry the document from day one.
- **Card source shape.** A card's source area is an oriented rectangle,
  `OrientedRect { center, width, height, angle_deg }` (points, top-left origin, angle
  clockwise). Grid cards always have `angle_deg = 0`. Freeform cards (M18) can be rotated
  to match a crooked scan. Reserve a `freeform` page-group kind holding a list of
  `OrientedRect`s; don't build its UI yet.

## Done when

- A PDF with a rules page, a 3×3 card section and a 2×2 section exports with the rules
  page skipped and each section on its own grid.
- A page that would overflow is listed before the save dialog opens.
- Undo/redo covers drawing, moving and resizing the selection and changing the grid.

## As built

Where the implementation settled on details the brief left open:

- **Groups cover every page.** `DocumentLayout` is `PageGroup[]` in order with no gaps
  (`src/lib/document-layout.ts`, all edits are pure functions). Kinds: `grid`
  (`pages`, `grid`, `selection`), `skip` and the reserved `freeform` (`cards: OrientedRect[]`,
  normalized to the page; `orientedToPoints` in `coordinates.ts` converts them). A new
  document is one grid group over all pages, so drawing a region still applies to every
  page until the user splits them.
- **Edits apply to the viewed page's whole group.** "Apply this grid to…" (this page, a
  range, all pages of the same size) copies the grid and region onto the targets as
  separate groups, so they can be edited on their own. "All pages of the same size" leaves
  skipped pages skipped. Including a skipped page joins the neighbouring grid group.
- **Per-group fields:** rows, columns and the source gap. Output gap, page and margins
  stay global and are part of undo.
- **Export.** `export_document(pages: PageJob[], output_path)`; `page_count` is gone.
  `validate_export(pages)` returns one `PageIssue { page_index, message }` per failing page,
  using the exporter's own checks (`fitting_layout`). The toolbar also reports pages with
  no region, and lists everything before the save dialog opens; clicking an entry jumps to
  the page.
- **History.** `zundo` on the layout store, recording only groups and output settings.
  Drags call `beginEdit` / `endEdit` so a whole drag is one step. History is cleared when a
  document opens.
- **Card identity.** `card_core::card::{CardId, OrientedRect, PageGroup}` with a `u32`
  `DocumentId` (`DEFAULT_DOCUMENT_ID = 0`); `SourceCard::id` and `SourceCard::oriented`
  bridge the grid generator to them. The TypeScript mirror is `src/lib/card.ts`.
