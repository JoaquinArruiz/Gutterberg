# 0.11.0 — Piece references on the sheets

Requested by a user: "view the card reference in the Print Preview pane (e.g. p1-r1c1, p2-r1c1) … It's hard to tell
what card is what from the thumbnails if the cards themselves look very similar from afar."

This version also releases what is in `CHANGELOG.md` under `Unreleased` today (the start-up log, macOS 13, the
`Gutterberg` settings folder). Nothing in this brief changes those.

## Goal

A switch on the Print tab shows each piece's reference on the large sheet, in the same words the piece library
already uses (`p3 · r1 c2`, `p4 · #2`), so a piece on the sheet can be found in the library and on the source page
at a glance. The references are only on screen, never in the exported PDF.

## Steps

1. **One reference for a piece.** Move the label that `CardThumb` builds (`library.thumb.label`,
   `gridPosition`, `freeformPosition`, `src/components/print/CardThumb.tsx`) into a helper in `src/lib/card.ts`,
   for example `pieceReference(id, documentLetter)`, and use it in the library. Tests next to it.
2. **Several PDFs.** With more than one document in the project, two pieces can both be `p1 · r1 c1`. Give each
   document a letter by its place in the project (A, B, C…) and put it in front of the reference
   (`A · p1 · r1 c1`) in the library, on the sheet and in the library's group headings. With one document there is
   no letter. This also helps the "same PDF added twice" workaround for several grids.
3. **The switch.** An icon button in the sheet preview's header bar (`SheetPreview.tsx`, next to the sheet
   position), "Show piece references", pressed or not. Saved in preferences as `print.showReferences`
   (preferences version 12, off by default, older files take the default). A help tip the first time the Print
   tab has a sheet with two or more pieces that look alike is not needed; the button's tooltip is enough.
4. **Drawing them.** A small dark chip with light text at the top-left corner of each placed piece, inside the
   piece, drawn above the pieces like `SheetOverlay` (its own component, `pointer-events: none`). The text size
   follows the zoom with a minimum; on a piece too small for the chip, show the shortest form (`r1c2`, `#2`) or
   nothing, never text that spills onto the next piece. Turned pieces keep the chip upright.
5. **Backs.** On a back sheet and in gutterfold, each back shows its own reference; the common back shows the
   reference of the piece it comes from with a mark that it is the common back (reuse `library.thumb.commonBadge`).
6. **Texts.** Every new string in `en.json` and `es.json`. Words: "piece", "sheet", "front / back".
7. **Docs and changelog.** A line in `docs/controls.md` (Print tab) and in `CHANGELOG.md` › Unreleased › Added.

## Out of scope

- References in the exported PDF (a "print references in the margin" option can be asked for later).
- References on the small sheet previews (the strip): too small to read.
- Clicking a piece on the sheet to select it in the library, or hovering to highlight it. Worth doing later; it
  needs the placements to take the pointer, which the drag-to-sort code should be checked against first.

## Done when

The switch shows and hides the references on fronts, backs and gutterfold sheets; two documents get letters; the
exported file is byte-for-byte what it was without the switch; every check in `AGENTS.md` passes.
