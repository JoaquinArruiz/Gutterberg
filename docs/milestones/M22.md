# M22 — UI consistency and polish

**Goal:** before the first public release (M15), make the interface consistent: shared
controls instead of browser defaults and copied styles, one recognizable look for AI
actions, explanations behind info tips instead of filling the sidebars, movable panels in
the Print tab, a fix for cropped top/bottom panels, and a tidier Preferences window with an
About section that links to the author.

No engine changes. Every new string goes into both `src/locales/en.json` and `es.json`
(neutral Spanish, `tú`). Keep the existing look wherever nothing below asks for a change.
Use pnpm for every package (never npm or npx).

## 1. Shared controls (`src/components/ui`)

Keyboard and screen-reader support built in. Radix UI primitives are fine (MIT,
`pnpm add`); hand-written components must use the right roles and keys.

| Component | Use | Replaces / examples |
| --- | --- | --- |
| **Button** | Variants `default`, `primary`, `ghost` (icon), `danger`, `ai` (section 2) | The `smallBtn` class string copied into 8 files (`DetectSection`, `PropertiesSidebar`, `PresetsSection`, `FreeformSection`, `PrintInspector`, `FinishSections`, `SelectedCardsSection`, `CardLibrary`) and `iconBtn` in 2 (`HintToast`, `DocumentName`) |

## As built

Where the implementation settled on details the brief left open, or went another way. The three extras of
section 6 were offered to the owner one by one and all three were approved, so they are built too.

### 1. Shared controls (`src/components/ui`)

- **Components.** `Button` (variants `default`, `primary`, `ghost`, `danger`, `ai`; `size` `sm` or `md`; `iconOnly` and
  `busy` for AI buttons), `Switch` (`role="switch"`), `Checkbox`, `Segmented`, `RadioCard` (with `RadioCardGroup`) and
  `InfoTip`. All are hand-written, no new dependency: `Switch` and `Checkbox` are buttons with the right role, `aria-checked`,
  a label that is a click target, and Space; `Segmented` and `RadioCard` are radio groups (`radio-keys.ts`: Tab reaches the
  chosen one, the arrows and Home/End move and select). Biome flags a styled `<button role="radio">`; each has a one-line
  `biome-ignore` saying why.
- **InfoTip.** Opens on hover, keyboard focus and click (a second click closes it), closes with Esc without the Esc reaching a
  dialog around it, and the text is always the button's description (`aria-describedby` to a visually hidden copy), so a screen
  reader reads it without opening anything. The bubble is `position: fixed`, flips above when there is no room below, and stays
  inside the window. `CollapsibleSection`, `NumberField` and `MeasurementInput` take an `info` prop; `Switch` and `Checkbox`
  take `info` (an InfoTip) or `hint` (a line that stays visible, used in Preferences, which has room).
- **What replaced what.** All native inputs went: 18, not 13, because M19 added five (the Detect engine radio, two in AI
  settings, Sort pages' Skip, the AI notice's "Don't ask again"). Switches: Link horizontal / vertical, Auto-fill, Group pieces
  by size, Print backs, Remember panel sizes / collapsed panels, AI Mode, Send page images. Checkboxes: Include page (thumbnails),
  Visible views (Preferences), Sort pages' Skip, Don't ask again. Segmented: Plan (all pieces / custom selection), Order of
  copies, Flip on, Bleed taken from, Orientation, Theme. RadioCard: Live preview (Preferences), the Apply grid target. Not
  Segmented: cut-mark style (three long labels) and the sheet grid and page size, which stay dropdowns.
- **Buttons.** `smallBtn` was in 9 files (the brief's 8 plus Sort pages), `btn` (the roomier one) in 4 dialogs plus the Detect
  draft bar, `iconBtn` in 2: all gone. The toolbar keeps its own `base`/`btn`/`iconBtn` (its look is not a copy of these), but
  its Export button is a `Button` `primary`, as are the buttons that confirm an action. About 33 raw `<button>`s remain for
  one-off widgets (menu items, tabs, thumbnails, the tools).

### 2. AI actions

- `--ai` (`#a78bfa` dark, `#7c3aed` light) and `--ai-soft` next to `--accent`. An AI `Button` has `Sparkles` in front of the text,
  a violet border and a soft hover; with `iconOnly` the spark is a small badge on the corner. `busy` pulses it, and

- Detect pieces: the Local / AI radio and the `engine` field of the AI store are gone. "Detect on this page" stays as it was;

### 3. Movable panels in the Print tab

- `workspace-layout.ts` knows two layouts, `cards` (Pages, Properties) and `print` (`library`, `inspector`), each with its own
  panel list, positions, sizes and presets; `WorkspaceLayout` takes a `layoutId` and `PrintStage` is now just it with the
  sheet preview as the editor. The sheet strip stays inside `SheetPreview`. Panel actions find their layout from the panel id
  (`layoutOfPanel`); `applyLayoutPreset` and `saveRegionSize` take the layout.
- **Where they can go.** The piece library: left, right, top, bottom or hidden. At the top or bottom it is a strip: the controls
  in a column on the left, the pieces at a fixed size (so a whole row fits) in a grid that scrolls down. The print settings
  are a vertical form like Properties: left, right or hidden. Presets: Classic, Right sidebar, Library on top, Focus.
- **Preferences version 9.** `print.layout` is a `WorkspaceLayoutPrefs`. `migratePreferences` turns the old
  `{ libraryWidth, inspectorWidth }` into the sizes of the left and right regions (the panels start where they always were);
  a version 9 file is never migrated again. The two "remember sizes / collapsed panels" switches are one setting for both
  tabs (the Source tab's copy wins when the data is normalized). Reset workspace layout resets both tabs.
- **The window's minimum size.** The centre keeps at least 360 px (the sheets had 320). A region now gives way down to its
  own minimum (`fitRegionSize`) before the panels collapse; before, panels collapsed as soon as their *preferred* sizes did not
  fit. For the Print tab's 320 + 300 at 900 px this is what keeps both panels open. The Source tab gets the same, gentler rule.
- The Panels menu and Preferences › Workspace follow the tab (Preferences shows both layouts). Two tour texts that said "on
  the left" and "on the right" no longer do.

### 4. Cropped top and bottom panels

- **Reproduced first** (a stubbed-IPC browser harness running the real React and CSS, 6 pages, 1280 × 800): top and bottom,
  Original / Preview / Split, Live Preview on and off, twelve combinations, all the same. The Pages panel was 124 px, its body
  96 px, and the row of thumbnails 123 px tall: the page numbers and the bottom of the thumbnails were cut off. Live Preview and
  the view change nothing, as the panel is outside them. **The cause was the brief's**, plus the horizontal scrollbar the
  brief counts too.
- **Fix.** The strip's height is built from its content in `workspace-layout.ts`: header 28 + `PAGE_THUMB_HEIGHT` 84 + the room
  around a thumbnail (40) + a reserved scrollbar (17) = 169 px, as default and minimum (so it cannot be dragged shorter); the
  library's strip comes from its thumbnail geometry the same way. `PagesPanel` and `CardLibrary` import those constants.
  `regionSize` never returns less than the minimum, so a 124 px remembered from before is raised too. After the fix the body
  is 141 px for 123 px of content in all twelve combinations.

### 5. Preferences

- Icons: `Settings`, `LayoutPanelLeft`, `Eye`, `Palette`, `Sparkles` (AI colour), and the app's own icon for About
  (`src-tauri/icons`). The navigation wraps long labels rather than cutting them. About is alone at the bottom after a spacer.
- About shows the app's icon, name and version (from Tauri, so it follows the app when it is renamed in M15), "Created by",
  and LinkedIn and GitHub buttons with their Simple Icons logos: the SVG paths are the published ones, checked
  character for character against the download; they take the text colour.
- **The links.** `openExternalLink` (`lib/external-links.ts`) refuses any address that is not one of the two without asking,
  asks in a native `ask` dialog ("This will open your web browser at:" and the exact address; Open / Cancel), and only then
  calls the opener plugin. `src-tauri/capabilities/default.json` grants `opener:allow-open-url` for exactly those two URLs and
  nothing else (not `opener:default`, which would allow any https address); a test compares that file with `ABOUT_LINKS`.
  New dependencies: `tauri-plugin-opener` (Cargo.lock grows by about 190 lines, mostly `zbus` on Linux) and
  `@tauri-apps/plugin-opener`.

### 6. Extras (all three approved)

- **Keyboard shortcuts sheet.** `?` (not while typing, not with Ctrl/Cmd/Alt; a second `?` closes it) or File › Keyboard
  shortcuts… opens it. The list is `lib/shortcuts.ts`, by area (General, Source tab, Print tab, Number fields), shown with Ctrl or
  Command by platform. It is kept in step with the code by hand; a test checks that it has a text in both languages for every
  shortcut and no text without one.
- **Start screen.** With no PDF open (and while one opens) `StartScreen` replaces the editor and its panels: Open PDF, Open
  project (with their shortcuts), the recent projects (name and folder), and a pointer to `?`.
- **Undo for the Print plan.** The print store has its own zundo timeline, limited to the plan (copies, mode, order, auto-fill,
  group by size, sheet grid, rows and columns, cut marks, bleed, duplex). `stores/history.ts` keeps one ordered journal across
  it and the layout's timeline, so Ctrl+Z undoes the last thing done in either, Ctrl+Shift+Z (or Ctrl+Y) puts it back, a new
  edit drops what could be redone, and a drag is one step as before. The toolbar buttons follow the journal. `undo`/`redo` come
  from there now. The plan's history is dropped when a document is reset or a project opened, when a PDF leaves the project, and
  when a freeform piece is deleted (the later pieces are renumbered, so old steps would name the wrong ones), as the layout's is.
  As before, undo is not tied to the tab: Ctrl+Z in the Source tab can undo a change made in the Print tab.
