# 0.14.0 — Several grids on one page

The second version for "several grids on one page", after 0.13.0 (turn a grid into pieces). Here each grid stays a
grid: its rows, columns, gaps and region can be changed later, and Detect pieces and "Apply this grid to…" know
about all of them.

## Goal

A page group holds any number of grids, each with its own region, rows, columns and gaps. The Source tab edits one
at a time; the others are drawn dimmer. Pieces from every grid go to the library and the sheets as today.

## Design to settle in step 1

- **Ids.** `CardId::Grid` gets a `grid` number (the grid's place in the group). Read with a default of 0 so old ids
  still parse. In `cardIdKey` (the key of per-piece edits) the number is left out when it is 0, so the edits of
  existing projects keep their keys and need no migration; check that this holds everywhere ids are compared
  (pairing, AI sorting, the order).
- **Groups.** `GridGroup` (`src/lib/document-layout.ts`) and `PageGroupKind::Grid` hold a list of
  `{ grid, selection }` instead of one. Project version 6 turns the single grid into a list of one.
- **The Preview view** (the re-spaced page in the Source tab) shows one grid re-spaced today. Find out how it treats
  a page with grid and freeform pieces, and give several grids the same treatment; write the answer here.
- **Order.** Pieces come out grid by grid (grid 1 row by row, then grid 2…), then the page's freeform pieces.

## Steps

1. Settle the design above with me; update this brief.
2. **Engine** (`card-core`): the list of grids in page groups, `extract_cards`, the grid number in ids, the project
   migration. Tests in `crates/card-core/tests/` for extraction, order and migration.
3. **Source tab**: a list of the page's grids in the sidebar ("Grid 1", "Grid 2", "Add grid", delete); the active
   grid is edited on the page as today, the others are drawn dimmer and a click picks one. Rows, columns, gaps,
   presets and "Apply this grid to…" act on the active grid; "Apply…" can copy all of them.
4. **Detect pieces** can propose more than one grid when it finds blocks of different sizes; still a proposal,
   applied only when the user says so. If this is large, it can move to a later version; the rest does not need it.
5. **Library and references**: with more than one grid on the page, the reference names the grid
   (`p1 · g2 · r1 c1`); `pieceReference` (`src/lib/card.ts`, from 0.12.0) does this in one place.
6. **Pairing backs** (`src/lib/pairing.ts`) and AI sorting order pieces by grid, then row and column.
7. While this is being built on `main`, it can sit behind a switch in Preferences › Experimental
   (`src/lib/experimental.ts`) so a hotfix release can go out without it. The switch is removed when it ships.
8. **Texts, docs** (`docs/controls.md`, `docs/architecture.md` › Pieces and page groups), **changelog**. Delete this
   brief and 0.13.0's leftovers, if any.

## Out of scope

- Grids at an angle (grids stay upright; crooked pieces are freeform).
- Turning freeform pieces into a grid.

## Done when

A page with three sizes of pieces can be marked with three grids, each edited later, and every piece prints at its
size; a version 5 or 6 project opens with its edits intact; every check in `AGENTS.md` passes.
