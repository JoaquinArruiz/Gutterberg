# M17 — Auto-detect card grids and card outlines (outline)

Firm this up with the owner before starting.

**Goal:** a "Detect cards" button proposes the card layout of a page, locally (no network,
no AI), for the user to confirm or adjust.

## Detector interface

Define one interface that every detection engine implements, so an optional AI engine
(M19*) can plug in later without changing the UI:

```
detect(page) -> Vec<Proposal>
Proposal { kind: Grid { bounds, rows, columns, source_gap } | Rects(Vec<OrientedRect>),
           confidence: 0..1, engine: "pdf-objects" | "edges" | "blobs" | ... }
```

The UI shows the best proposal as an editable draft (grid group or freeform cards, M11 and
M18). It is never applied without the user confirming, and undo covers it.

## Local engines, tried in this order

1. **PDF objects (exact).** Many publisher PDFs place each card's art as its own image, or
   draw cut lines and crop marks as paths. List the page's objects with pdfium. Several
   same-size images in a regular arrangement give the grid directly, to a fraction of a
   millimetre. Crop marks in the margins confirm the boundaries.
2. **Repeating edges (flat pages, edge-to-edge sheets).** Render the page small and in
   grey. For every pixel column, sum the horizontal edge strength over the page height:
   card borders line up and show as tall peaks at a regular spacing, while the art averages
   out. The spacing gives the card width and the peak count the columns (autocorrelation
   helps find the period); same for rows. With gaps or white borders, strips of plain
   background between cards make it easier still.
3. **Blobs (messy scans).** Separate the scanner background (usually plain), find each
   connected blob, and fit the minimum-area rotated rectangle around it. That gives one
   `OrientedRect` per card, tilt included.

Known weak spots, reported as low confidence rather than guessed: art that runs across card
borders with no visible line, cards touching on a scan, white cards on a white scanner bed.

Pure Rust (`imageproc` for edges and contours); no OpenCV. Each engine runs in milliseconds
on a low-resolution render.

## Done when

- A vector PnP sheet is detected exactly by the PDF-objects engine.
- An edge-to-edge 3×3 raster sheet is detected by the edges engine to within 0.5 mm.
- A scan with tilted cards on a plain background produces one rotated rectangle per card.
- A low-confidence case says so instead of applying a wrong grid.
