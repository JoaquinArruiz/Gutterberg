# M25 — Welcome tour, Help section and bug reports

**Goal:** a short welcome tour made from video clips on the first start, and a **Help**
section in Preferences that holds everything about learning the app and asking for help:
replay the tour, bring the help tips back, the keyboard shortcuts, and "Found a bug?" with a
GitHub issue form (and a Discord button for later).

No engine changes. Use pnpm for every package (never npm or npx). Every new string goes into
both `src/locales/en.json` and `es.json`.

## 1. Welcome tour

### The clips

The owner's exports are in **`assets/welcome/`**, one per step, named `<nn>-<name>.mp4`.
They are the masters: never edit them by hand, and don't ship them as they are (1920 × 1080,
with a silent audio track). A short abstract story, not a tour of the app's buttons:

| File | What it shows | Step title (suggestion) | Text (suggestion) |
| --- | --- | --- | --- |
| `01-cut.mp4` (2.3 s) | A page with a square; it is cut into 9 rectangles, which spread apart | Your PDF, cut into pieces | Mark where the pieces are on a page: a grid, Detect pieces, or one by one with the piece tool |
| `02-place.mp4` (3.0 s) | The 9 rectangles are put on an A4 page | On the sheet you print | Pick a sheet size such as A4 or Letter. Your pieces keep their exact size |
| `03-arrange.mp4` (4.7 s) | Numbered rectangles in a shuffled order (3 1 2 / 5 6 4 / 9 7 8) are sorted into 1 to 9 | Arrange them your way | Put the pieces in the order you want, set the gap between them, and choose which ones to print and how many copies |
| `04-done.mp4` (3.0 s) | The rectangles in place turn green, and a check appears in the middle | Ready to cut | Export a PDF with cut marks, bleed or duplex if you want. Your artwork is never changed |

The titles and texts are suggestions for the owner to review; Spanish versions too.

- Checked when this brief was updated: four different clips, 1920 × 1080, H.264, 30 fps,
  0.24–0.52 MB each, with a silent audio track.
- **`scripts/encode-welcome.sh`** turns every master into what the app ships, so a new export
  only needs the script run again. It uses `ffmpeg` (the owner installs it; say so in the
  script's header):
  - `public/welcome/<nn>-<name>.webm` (VP9) **and** `.mp4` (H.264, `+faststart`), both
    1280 × 720, 30 fps, **no audio**. Both formats, because the Linux webview (WebKitGTK)
    may not play H.264 and older macOS may not play VP9.
  - `public/welcome/<nn>-<name>.png`: the clip's **last frame**, the poster (and what shows
    after the clip ends and with reduced motion).
  - Commit the outputs (the app needs them to build without ffmpeg).
- Size budget: about 1.5 MB per clip and 8 MB in total (they go into every installer and the
  repo). The masters are 0.24–0.52 MB each, so this is far off.
- **No text inside the clips.** Titles and explanations come from the language files, so the
  tour works in English and Spanish.
- The steps are a list in `src/lib/welcome.ts` (id, clip name, title key, text key), in the
  order of the table. The dialog keeps the clips' 16:9 shape.
- Check the CSP in `tauri.conf.json`: add `media-src 'self'` so the videos load.

### How it behaves

- A dialog over the start screen. Each step: the clip, a title, one or two lines of text, and
  **Back / Next** (Next becomes **Get started** on the last step), dots for the steps, and
  **Skip** at any time. Esc closes it like Skip.
- Each clip plays **once** when its step opens and stops on its last frame; it doesn't move on
  by itself. A small "Play again" button replays it.
- **Reduced motion** (`prefers-reduced-motion`): show the poster and a Play button, don't
  autoplay.
- **First start only.** Saved as `prefs.help.welcomeSeen` (a number: the tour's version, so
  a much changed app can show a new tour one day). Closing it in any way (Skip, Esc, Get
  started) marks it seen. Preferences version bump with a migration test.
- It only opens over the **start screen**, with nothing open. If the app starts with a file
  (from M15's file association, double-clicking a `.gtr`), don't show it then; show it the
  next time the start screen appears. Write it so M15 only has to open the file.
- **Help tips (M20) wait.** No hint toast or tour shows while the welcome is open, and the
  first one doesn't fire the moment it closes. The first-PDF tour still runs when a PDF is
  opened.
- Keyboard: focus starts on Next, Tab stays inside the dialog, the dots and buttons have
  labels for screen readers.

## 3. Found a bug?

In the Help section:

- A short text: if something doesn't work, open an issue on GitHub (needs a free GitHub
  account) and say:
  - which version you use and on which system (the button below copies it)
  - what you did, step by step, so someone else can make it happen again
  - what you expected, and what happened instead
  - whether you found a way around it
  - the PDF or project, if you can share it (only files you're allowed to share), or a
    screenshot
- **Copy app info:** copies to the clipboard, e.g.
  `Gutterberg 1.0.0 · Windows 11 (x86_64) · Language: es · pdfium 7xxx`. Use Tauri's `os`
  plugin (`tauri-plugin-os`, `@tauri-apps/plugin-os`) for the system and
  `navigator.clipboard.writeText` for the copy, with a "Copied" confirmation. Also shown as
  selectable text.
- **Report on GitHub:** opens
  `https://github.com/JoaquinArruiz/Gutterberg/issues/new?template=bug_report.yml&version=…&os=…`.
  GitHub fills issue-form fields from the address, so the version and system arrive filled in.
  - Through `openExternalLink` (M22): it asks first and shows the exact address. Rename
    `ABOUT_LINKS` to `EXTERNAL_LINKS` and allow this one by **prefix** (the query changes);
    the other links stay exact.
  - The opener permission in `src-tauri/capabilities/default.json` gets this one address with
    a wildcard after `issues/new`; update the test that compares the file with the links.
- **Discord:** a button with the Discord logo (Simple Icons, like About), **disabled**, with
  "Coming soon". The address is a constant, `DISCORD_URL = null`; when the owner sets it, the
  button turns on (and the address goes into the opener permission and the links test).

### The issue form (`.github/ISSUE_TEMPLATE/`)

- `bug_report.yml`, a GitHub issue form, English, with a note that Spanish is fine too:
  - **Version** (`id: version`, text, required)
  - **Operating system** (`id: os`, text, required, e.g. "Windows 11", "macOS 15", "Ubuntu 24.04")
  - **What happened** (required)
  - **Steps to reproduce** (required, numbered)
  - **What you expected** (required)
  - **Workaround** (optional): "Did you find a way around it?"
  - **Files** (optional): attach the PDF or project if you're allowed to share it, or a
    screenshot
  - A checkbox: "I searched the open issues and this isn't one of them"
  - Label `bug`.
- `feature_request.yml` (short: what you want to do, why, how you do it today) and
  `config.yml` with blank issues turned off.
- The ids `version` and `os` must match the query parameters the app sends.

## As built

**Welcome tour**
- `scripts/encode-welcome.sh` turns each master in `assets/welcome/` into `public/welcome/<nn>-<name>.webm`
  (VP9), `.mp4` (H.264, `+faststart`) and `.png` (last frame), 1280 × 720, 30 fps, no audio, and fails if a clip
  is over 1.5 MB or the folder over 8 MB. The outputs are committed: 474 KB in all. The masters are untouched.
- `src/lib/welcome.ts` has the four steps (cut, place, arrange, done) and `WELCOME_VERSION = 1`.
  `WelcomeDialog` is a modal `<dialog>` with the clip (webm first, then mp4, poster = last frame), title and
  text, Back / Next (Get started on the last step), a dot for each step (labelled "Step n of 4: title"), Skip
  and Play again. Focus starts on Next. Esc, Skip and Get started all call the same close, which saves
  `prefs.help.welcomeSeen = WELCOME_VERSION`. Each clip plays once and stays on its last frame; with
  `prefers-reduced-motion` nothing plays until Play is pressed.
- It opens by itself (`useWelcomeAutoOpen`) only with nothing open and `welcomeSeen < WELCOME_VERSION`.
  **For M15**: when the app is started with a file, call `useUiStore.getState().deferWelcome()` before the file
  opens; the deferral is dropped as soon as a document is open, so the next start screen shows the tour.
- Help tips wait: `useHint` is hidden while `ui.hintsHeld`, which is true while the welcome is open and for 2.5 s
  after it closes (`WELCOME_HINT_DELAY_MS`). The first-PDF tour is a hint too, so it also waits those 2.5 s if a
  PDF is opened that fast; after that it runs as before.
- Preferences version 10 adds `help.welcomeSeen`. Existing users get the tour once too, since they never closed
  it; "Reset to defaults" keeps it, like the recent files. CSP now has `media-src 'self'`.
- The start screen's pointer line has "Replay welcome tour" next to the `?` hint.

**Preferences › Help** (icon `LifeBuoy`, after AI): the four groups in the brief's order. The help tips reset
moved here from General with its strings (under `preferences.help.*`); the shortcuts list is the shortcuts
sheet's own component (`ShortcutsList`), shown in the section. Replay closes Preferences first, because the tour
opens above everything.

**Found a bug?**
- Copy app info: `Gutterberg 1.0.0 · Windows 11 (x86_64) · Language: es · pdfium 8086`, also shown as selectable
  text, with "Copied" for 2 s and a message if the clipboard refuses. The system comes from `tauri-plugin-os`
  (Windows 10 / 11 by build number, `macOS <version>`, `Linux <version>`), the language from i18n and the pdfium
  build from a new `app_info` command that reads it from `scripts/fetch-pdfium.sh`'s pinned tag at build time
  (`src-tauri/build.rs`), so it cannot drift from what is bundled.
- Report on GitHub goes through `openExternalLink`, which asks first and shows the exact address.
  `ABOUT_LINKS` is now `EXTERNAL_LINKS` (the two About links, exact). The issue form's address is allowed by its
  start (`BUG_REPORT_URL` + `&`, host and scheme checked, no fragment); the version and system are escaped. The
  opener permission has `…/issues/new?template=bug_report.yml&*`, and the links test compares the file with the
  constants. The permissions for the system info are the three exact ones (`os:allow-arch`, `-os-type`,
  `-version`).
- Discord: `DISCORD_URL = null`, so the button (Simple Icons logo) is disabled and says "Coming soon". Setting
  the constant turns it on and puts the address in the exact list; its permission and the links test are the one
  thing still to add by hand then.
- `.github/ISSUE_TEMPLATE/`: `bug_report.yml` (ids `version` and `os` match the address), `feature_request.yml`
  and `config.yml` with blank issues off.

**What changed from the plan**
- The brief had been written for placeholder clips and six steps; the owner's four clips replaced them, so the
  tour has four steps and no placeholders. Titles and texts are the brief's suggestions, with Spanish versions
  for the owner to review (in the Spanish, "doble cara" is used for duplex, as elsewhere in the app).
- The clips are 4:3 art inside a 16:9 frame with black bars on both sides. The dialog shows them as they are
  (the masters are not to be edited); cropping the bars in `encode-welcome.sh`, or a 16:9 export from Figma,
  would use the dialog's space better.
- "Copy app info" cannot show the pdfium version of a build made without the script's tag line; it then leaves
  `pdfium` out.
