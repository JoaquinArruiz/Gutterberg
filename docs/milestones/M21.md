# M21 — Terminology and languages: Source / Print, "pieces", English and Spanish

**Goal:** the words the user sees match what the app has become, and the app speaks English
and Spanish, chosen in Preferences. Every user-facing string moves into a translation
catalog in the same pass that renames it, so no string is touched twice.

Do this next (before M14), so later milestones add strings to the catalogs from the start.
Follow the **Glossary** in `CLAUDE.md` (both columns); it is the source of truth for every
word below. No behaviour changes beyond language and number format.

## Part A — terminology (English)

- **Tabs:** "Cards" → **Source** (`EditorToolbar.tsx`, the stage tabs). "Print" stays. The
  internal stage id may stay `cards`; if it is renamed to `source`, migrate stored
  preferences that reference it.
- **Views inside the Source tab:** "Source / Output / Split" → **Original / Preview / Split**
  (`WORKSPACE_LABEL` in `src/lib/preferences.ts`, Preferences › Workspace, the layout
  preview, hints). Keep the internal mode ids (`source`, `output`, `split`).
- **"card" → "piece"** in user-facing text: the piece library, the piece tool (keep its `C`
  shortcut), freeform pieces, "Group pieces by size", "Selected pieces", "n sheets, m
  pieces", "piece width / height", tooltips, empty states, errors and pre-flight messages,
  the Apply grid dialog, the About section. About 140 strings in about 25 components today
  (`src/components/**`, `src/App.tsx`). Keep "card" only for real-world examples ("poker
  cards", "card backs").
- **Docs:** `README.md` (description, controls table, status list wording),
  `docs/milestones/README.md` direction section. Leave finished briefs as written; add a
  one-line note at the top of M13 and M18 that the UI now says "Source" and "pieces".

## Part B — translations

- **Library:** `i18next` + `react-i18next` (both MIT): `pnpm add i18next react-i18next`.
  Use typed keys (i18next's TypeScript resource typing), so a missing or misspelled key is a
  type error.
- **Catalogs:** `src/locales/en.json` (source and fallback) and `src/locales/es.json`,
  grouped by area (`toolbar`, `source`, `print`, `preferences`, `hints`, `errors`, ...).
  Use i18next interpolation and plurals (`{{count}} pieces`, `pieces_one` / `pieces_other`);
  never build sentences by concatenating strings.
- **Move every user-facing string** into `en.json` while doing Part A: components, the M20
  hints catalog (it now stores keys, not text), dialog titles, `aria-label`s and `title`
  tooltips, native dialog filter names ("PDF", "Gutterberg project" later).
- **Rust errors become codes.** Errors that reach the UI are sent as a code plus values
  instead of an English sentence, e.g. `{ "code": "does_not_fit", "needed_w_mm": …, … }`
  (serialize `card_core::Error` and the command errors with a stable `code` field); the UI
  formats them from `errors.*` keys. Unknown codes fall back to the English text, so nothing
  is ever blank. Keep the `Display` text for logs and tests.
- **Spanish:** neutral Latin American Spanish, the form that reads naturally everywhere:
  `tú` imperatives ("elige", "arrastra"), no voseo, no `vosotros`, no regional slang;
  "computadora", "archivo". Use the glossary's Spanish column for every product term. The
  owner (a native speaker) reviews `es.json` before release; mark anything uncertain in a
  short list in this brief instead of guessing silently.
- **Language preference:** Preferences › General › **Language**: System (default) /
  English / Español. "System" follows the OS language (`navigator.language`), falling back
  to English. Switching applies immediately, no restart. Stored in preferences (bump the
  version, migrate with System as the default).
- **Check:** a unit test that `es.json` has exactly the keys of `en.json` (no missing, no
  extra) and that interpolation placeholders match key by key.

## Part C — numbers: dot or comma

- **Preference:** Preferences › General › **Decimal separator**: Automatic (from the
  language: comma for Spanish, dot for English) / Dot (63.5) / Comma (63,5).
- **Display:** every number the UI shows (`formatMeasurement` in `src/lib/measurement.ts`,
  percentages, sizes in tooltips) uses the chosen separator.
- **Input accepts both, always.** Measurement and number fields accept `63.5` and `63,5`
  whatever the setting, so pasting from anywhere works. There are no thousands separators in
  these fields; a value with both `.` and `,`, or more than one separator, is rejected with
  the usual field error. Put the parsing in one tested function next to `formatMeasurement`.
- The internal values stay plain numbers; this is display and input only. Project files
  (M14) and exports never depend on the setting.

## Part D — layout check

- Spanish text runs 20–30% longer. Check in Spanish that tabs, toolbar buttons, sidebar
  labels, inspector sections, dialogs and hint toasts don't clip or overlap, at the
  minimum window size (900 × 560). Prefer wrapping or `title` tooltips over shrinking text.

## Not in scope

- Renaming code identifiers, files or crates (`CardId`, `card-core`, `CardLibrary.tsx`).
- The product rename to Gutterberg (M15, step 0).
- Translating the README or milestone docs; they stay in English.
- Non-rectangular pieces.

## Done when

- The app shows "Source | Print" tabs, "Original / Preview / Split" views, and "pieces"
  throughout; a search of user-facing strings finds "card" only in real-world examples.
- No user-facing string is left hard-coded in components; switching the language to
  Español changes every visible text immediately, including hints, tours and error
  messages coming from Rust.
- Both separators are accepted in every number field in both languages; the display follows
  the preference.
- The key-parity test passes; stored preferences from before still load.
- The Spanish layout check is done at the minimum window size.
- Every check in `CLAUDE.md` passes.
