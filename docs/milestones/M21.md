# M21 — Terminology and languages: Source / Print, "pieces", English and Spanish

**Goal:** the words the user sees match what the app has become, and the app speaks English
and Spanish, chosen in Preferences. Every user-facing string moves into a translation
catalog in the same pass that renames it, so no string is touched twice.

Do this next (before M14), so later milestones add strings to the catalogs from the start.
Follow the **Glossary** in `CLAUDE.md` (both columns); it is the source of truth for every
word below. No behaviour changes beyond language and number format.

## Part A — terminology (English)

- **Tabs:** "Cards" → **Source** (`EditorToolbar.tsx`, the stage tabs). "Print" stays. The
  internal stage id may stay `cards`; if it is renamed to `source`, migrate stored
  preferences that reference it.
- **Views inside the Source tab:** "Source / Output / Split" → **Original / Preview / Split**
  (`WORKSPACE_LABEL` in `src/lib/preferences.ts`, Preferences › Workspace, the layout
  preview, hints). Keep the internal mode ids (`source`, `output`, `split`).
- **"card" → "piece"** in user-facing text: the piece library, the piece tool (keep its `C`
  shortcut), freeform pieces, "Group pieces by size", "Selected pieces", "n sheets, m
  pieces", "piece width / height", tooltips, empty states, errors and pre-flight messages,
  the Apply grid dialog, the About section. About 140 strings in about 25 components today
  (`src/components/**`, `src/App.tsx`). Keep "card" only for real-world examples ("poker
  cards", "card backs").
- **Docs:** `README.md` (description, controls table, status list wording),
  `docs/milestones/README.md` direction section. Leave finished briefs as written; add a
  one-line note at the top of M13 and M18 that the UI now says "Source" and "pieces".

## Part B — translations

- **Library:** `i18next` + `react-i18next` (both MIT): `pnpm add i18next react-i18next`.
  Use typed keys (i18next's TypeScript resource typing), so a missing or misspelled key is a
  type error.
- **Catalogs:** `src/locales/en.json` (source and fallback) and `src/locales/es.json`,
  grouped by area (`toolbar`, `source`, `print`, `preferences`, `hints`, `errors`, ...).
  Use i18next interpolation and plurals (`{{count}} pieces`, `pieces_one` / `pieces_other`);
  never build sentences by concatenating strings.
- **Move every user-facing string** into `en.json` while doing Part A: components, the M20
  hints catalog (it now stores keys, not text), dialog titles, `aria-label`s and `title`
  tooltips, native dialog filter names ("PDF", "Gutterberg project" later).
- **Rust errors become codes.** Errors that reach the UI are sent as a code plus values
  instead of an English sentence, e.g. `{ "code": "does_not_fit", "needed_w_mm": …, … }`
  (serialize `card_core::Error` and the command errors with a stable `code` field); the UI
  formats them from `errors.*` keys. Unknown codes fall back to the English text, so nothing
  is ever blank. Keep the `Display` text for logs and tests.
- **Spanish:** neutral Latin American Spanish, the form that reads naturally everywhere:
  `tú` imperatives ("elige", "arrastra"), no voseo, no `vosotros`, no regional slang;
  "computadora", "archivo". Use the glossary's Spanish column for every product term. The
  owner (a native speaker) reviews `es.json` before release; mark anything uncertain in a
  short list in this brief instead of guessing silently.
- **Language preference:** Preferences › General › **Language**: System (default) /
  English / Español. "System" follows the OS language (`navigator.language`), falling back
  to English. Switching applies immediately, no restart. Stored in preferences (bump the
  version, migrate with System as the default).
- **Check:** a unit test that `es.json` has exactly the keys of `en.json` (no missing, no
  extra) and that interpolation placeholders match key by key.

## Part C — numbers: dot or comma

- **Preference:** Preferences › General › **Decimal separator**: Automatic (from the
  language: comma for Spanish, dot for English) / Dot (63.5) / Comma (63,5).
- **Display:** every number the UI shows (`formatMeasurement` in `src/lib/measurement.ts`,
  percentages, sizes in tooltips) uses the chosen separator.
- **Input accepts both, always.** Measurement and number fields accept `63.5` and `63,5`
  whatever the setting, so pasting from anywhere works. There are no thousands separators in
  these fields; a value with both `.` and `,`, or more than one separator, is rejected with
  the usual field error. Put the parsing in one tested function next to `formatMeasurement`.
- The internal values stay plain numbers; this is display and input only. Project files
  (M14) and exports never depend on the setting.

## Part D — layout check

- Spanish text runs 20–30% longer. Check in Spanish that tabs, toolbar buttons, sidebar
  labels, inspector sections, dialogs and hint toasts don't clip or overlap, at the
  minimum window size (900 × 560). Prefer wrapping or `title` tooltips over shrinking text.

## Not in scope

- Renaming code identifiers, files or crates (`CardId`, `card-core`, `CardLibrary.tsx`).
- The product rename to Gutterberg (M15, step 0).
- Translating the README or milestone docs; they stay in English.
- Non-rectangular pieces.

## Done when

- The app shows "Source | Print" tabs, "Original / Preview / Split" views, and "pieces"
  throughout; a search of user-facing strings finds "card" only in real-world examples.
- No user-facing string is left hard-coded in components; switching the language to
  Español changes every visible text immediately, including hints, tours and error
  messages coming from Rust.
- Both separators are accepted in every number field in both languages; the display follows
  the preference.
- The key-parity test passes; stored preferences from before still load.
- The Spanish layout check is done at the minimum window size.
- Every check in `CLAUDE.md` passes.

## As built

What the brief left open, and what was decided while building it.

**Libraries and layout.** `i18next` 26.4 and `react-i18next` 17.0 (added with pnpm). `src/i18n.ts` creates
the instance, exports `t` for stores and `lib` code (components use `useTranslation`) and `applyLocale`;
`src/i18next.d.ts` types the keys from `en.json`, so a wrong key is a `tsc` error (this includes the hint
catalog, whose steps now hold keys). `src/test-setup.ts` loads English before every test file
(`vite.config.ts` now imports `defineConfig` from `vitest/config`). Catalogs are grouped by area
(`toolbar`, `source`, `freeform`, `pages`, `applyGrid`, `library`, `print`, `sheets`, `preferences`,
`panels`, `hints`, `errors`, ...). Plurals are `_one` / `_other` (no `_many`, so the two catalogs have the
same keys); the sheets/pieces summary is two plural keys joined by a third.

**Part A.** Done as written, plus these choices: the stage id stays `cards`; the tool is "Piece tool"
(`C` kept); the sidebar's "Source spacing" is now **Source gap** and the Print inspector's "Spacing
between cards" is **Output gap**, to use the glossary's terms; the preview pane's title is "Preview"
(not "Output"); the Preferences text said "Update preview" for a button that is called "Refresh preview",
so it now says that. `WORKSPACE_LABEL`, `UNIT_LABEL`, `POSITION_LABEL`, `PRESET_LABEL` and the panel
`title`s are gone from `lib/`: the labels are catalog keys. The M13 and M18 briefs got the one-line note.

**Part B.**
- *Rust errors.* `card_core::ErrorInfo { code, message, ...values }` (page numbers 1-based). `Error`
  serializes to it and every command returns it (`src-tauri/src/state.rs::internal` covers lock and task
  failures with code `internal`). `PageIssue` carries the same `code` and values next to `message`.
  Codes: `does_not_fit`, `page_out_of_range`, `unsupported_rotation`, `unsupported_user_unit`, `pdf`,
  `io`, `invalid_grid`, `invalid_sheet`, `pdfium`, `malformed`, `superseded`, `worker_stopped`,
  `no_document`, `same_file`, `no_pages`, `nothing_to_print`, `internal`; `export_print` adds `at_page`
  when it stops at one page. The UI makes two of its own (`freeform_only`, `no_region`).
  `src/lib/errors.ts` turns anything a call rejects with into an `AppError` and words it from
  `errors.<code>`; an unknown code shows the English `message`. Sizes in mm are shown with the user's
  decimal separator. The stores keep the `AppError` (not text), so an error already on screen changes
  language with the app.
- *Left in English on purpose.* `pdf`, `io`, `invalid_grid`, `invalid_sheet`, `pdfium` and `malformed`
  wrap an English technical detail (`{{detail}}`) from lopdf, the OS or the engine's own checks; the frame
  around it is translated, the detail is not. Making these fully translatable means a code per site in
  `layout.rs`, `sheet.rs` and `export.rs`; none of them is something the UI normally lets the user cause.
- *Language preference.* Preferences are version 6 with `locale: { language, decimal }`, both defaulting
  to "system" / "auto"; a version 5 file loads with those defaults. `<html lang>` follows the language.
- *Dialog texts.* The file filter name and the suggested export file name (`-spaced.pdf` /
  `-print.pdf`, fallback `cards`) are catalog texts too (`files.*`).

**Part C.** `formatDecimal` and `parseDecimal` live in `lib/measurement.ts`. `parseDecimal` accepts one
`.` or `,` (so `63.5`, `63,5`, `.5`, `5,`, a sign, surrounding spaces) and nothing else: no thousands
separators, no exponents or hex (`1e3` used to be accepted by the old `Number(...)`). `NumberField` only
commits when the typed number differs from the one shown, so typing the shown text with the other
separator does not rewrite an exact value. The separator in effect is module state in `lib/locale.ts`,
kept in step by the preferences store; `useUnit()` also subscribes to it so every measurement redraws.
Percentages (scale, card size summaries) use it too.

**Part D.** Checked at 900 × 560 by running the real UI in headless Chrome with Tauri's IPC mocked
(source view with tours, split view, piece tool, Print tab with the tour and with a custom plan,
Preferences General / Workspace, Apply grid, export problems, Panels menu). The harness was a throwaway
and is not in the repo. What it found and what changed:
- The toolbar did not fit (with buttons that cannot wrap it needs about 1010 px in Spanish and 930 px in
  English, in a 900 px window; before, the labels wrapped and clipped): icon-only
  buttons are tighter (`px-1.5`), separators narrower, buttons never wrap, and below 1100 px "Open PDF"
  shows only its icon (its name stays as tooltip and accessible name).
- The sheet header in the Print tab clipped "Hoja 1 de 3" and the summary: it now wraps to a second line.
- A wide option ("Automática…") stretched the inspector sideways: `Select` can shrink (with the full
  label as tooltip) and the label/select rows in the inspector wrap.

**Checks.** `pnpm typecheck`, `pnpm test`, `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`
and `cargo test --workspace` (with `PDFIUM_LIB_PATH`) pass. `pnpm lint` passes with the 3 warnings and 1
info that were already there. New tests: key parity and placeholder parity of the two catalogs, glossary
terms, `locale`, `parseDecimal` / `formatDecimal`, `errors`, `NumberField` with both separators,
language switching on the toolbar, Preferences, the v5 → v6 preferences migration, and the Rust error
payloads (`crates/card-core/tests/errors.rs`).

### For the owner to review (Spanish and wording I was unsure about)

Nothing below was guessed silently; these are the places where a native speaker may want another word.

1. **Product terms outside the glossary:** "Región de cuadrícula" (grid region tool), "Desplazar" (Pan
   tool), "Disposición de origen" (Source layout), "Disposición" (workspace layout), "Salida" (the
   sidebar's Output section), "Preajuste" (preset), "Enfoque (sin paneles)" (Focus), "Espacio de trabajo".
2. **Gap:** the glossary terms are used for the two section headings ("Separación de origen", "Separación
   de salida"), and plain "Separación" for the gap fields.
3. **Paper sizes:** "Carta" and "Legal" (some countries say "Oficio" for Legal).
4. **Verbs:** "Omitir" / "Incluir" (skip / include a page), "Girar" (turn, also used for rotate), "Rellenar
   automáticamente" (auto-fill), "Agrupadas" / "Intercaladas" (grouped / interleaved), "Todas verticales" /
   "Todas horizontales" (make all portrait / landscape), "Listo" (Done), "Omitir" for Skip in a tour.
5. **"Vista previa en vivo"** (Live preview) and "Actualizar vista previa" (the refresh button).
6. **Keys:** "Mayús" for Shift; Ctrl and Cmd are unchanged.
7. **Thumbnail label** `p1 · f1 c1`: `f` is fila (row), `c` columna.
8. **Units:** "Pulgadas (in)" keeps the symbol `in`.
9. **Default decimal for Spanish is the comma**, as the brief says; Mexico and some other countries use a
   dot, so "Automatic" may not suit every Spanish speaker (they can pick Dot).
10. **Export file names:** `-espaciado.pdf` and `-impresion.pdf` have no accent on purpose (safe in any
    file system); the fallback name is `piezas`.
11. **"pestaña"** (tab) in "Abrir la pestaña Imprimir", and **"biblioteca de piezas"** written in full in the
    hints and empty states (it is never shortened to "la biblioteca").
12. **English wording I chose:** "Piece tool", "Output gap" / "Source gap", "Auto-fit to pieces",
    "Make all portrait / landscape" (unchanged), and the one-sentence "freeform piece" messages.
