# M19 — AI Mode (optional)

Status: **done** (plan approved by the owner; see "As built" at the end). The owner asked for it, so it is no longer "maybe".

**Goal:** an opt-in AI Mode that adds two AI-assisted buttons, using the user's own API key. No chat. Every
result arrives as an editable proposal; the AI never changes the project directly.

```
button -> notice + estimate -> user confirms -> Rust: render pages -> adapter -> provider
       -> JSON reply -> validated -> Proposal / page labels -> draft in the UI -> Apply (one undo step)
```

## Principles (kept from the outline) and how they are enforced

- **Off by default; hidden, not greyed.** Every AI control is rendered only when `prefs.ai.enabled`. The one
  exception is the switch itself: Preferences gets one section, **AI Mode**, that is always listed (it is the only
  way to turn it on). With the switch off that section shows the switch and one sentence, nothing else.
- **No network when off, provably.** The webview's CSP has no `connect-src`, so the page cannot reach the network, and
  that stays. All traffic goes from Rust, in one new crate, `crates/card-ai`; `card-core` stays free of network code.
  The Rust side also keeps an `ai_enabled` flag (set by `ai_set_enabled` when the preference changes and at start-up);
  every `ai_*` command refuses with `ai_disabled` when it is false. A test counts connections to a local listener and
  expects zero. The local engines (M17's `default_engines`) never include an AI engine.
- **Buttons, not chat.** One request per action, a fixed prompt, a JSON Schema for the reply. The reply is parsed and
  validated; anything wrong is an error and the project is untouched.
- **Same review UI.** Detect returns the M17 `Proposal` (engine `ai`), so the draft, its confidence word, Apply, Next
  and Discard are the ones that exist. Sort pages gets a small review list.
- **Privacy.** Before anything is sent, an in-app notice says which provider (and host) gets what: which pages, as
  images at what size, or text only. A **text-only** setting never sends pixels.

## What the user sees

- **Preferences › AI Mode:** switch; provider (Anthropic, OpenAI-compatible, Gemini, Ollama); model (text, with the
  provider's default filled in); base URL (OpenAI-compatible and Ollama; empty = the provider's own); **API key**
  (write-only field, then "Key saved in the system keychain" with Replace and Remove; Ollama needs none); **Send page
  images** (on by default; off = text only); **Test connection** (one tiny text request, reports success or the error).
- **Detect pieces** (M17's section) gets an engine choice, **Local | AI**, shown only when AI Mode is on. Local is
  unchanged and still the default. AI sends the viewed page and shows the result as the usual draft, engine "from AI".
- **Sort pages:** a new sidebar section, shown only when AI Mode is on, with **Sort pages with AI**. It labels every page
  `cards`, `backs`, `rules`, `cover` or `other` from small thumbnails and shows a list: thumbnail, page number, label
  (a dropdown), and a **Skip** checkbox pre-filled from the label (rules, cover and other skipped; cards and backs kept,
  because backs are pieces for duplex). The user edits the list; **Apply** sets those skip states in one undo step
  (the M11 skip toggles; grids and regions are untouched). Nothing is applied until then.
- **Every AI action asks first.** A dialog: provider and host, "Pages 3 to 52 will be sent as images, about 1000 px" or
  "Text only: no images are sent", the number of requests, an estimate of the tokens (and of the cost when the model
  has a known price), **Send** and **Cancel**. For Detect on a single page there is a session-only "Don't ask again
  until I close the app". Afterwards the real usage is shown ("used 4,812 input and 310 output tokens").
- **Errors** (no key, keychain unavailable, HTTP error with the provider's message, timeout, a refusal, a reply that is
  not JSON or does not fit the schema, a proposal outside the page) show as a clear message next to the button. The
  project, the draft and the layout are left as they were.

## Design

### `crates/card-ai` (no Tauri, no UI; depends on `card-core` for `Proposal` and geometry)

```rust
pub enum ProviderKind { Anthropic, OpenAiCompatible, Gemini, Ollama }
pub struct ProviderConfig { kind, model: String, base_url: Option<String> }
pub struct AiRequest { instruction: String, images: Vec<Image { mime, bytes }>, schema: serde_json::Value, max_output_tokens: u32 }
pub struct AiReply { json: serde_json::Value, usage: Usage { input_tokens, output_tokens } }
pub trait Transport { fn post(&self, url: &str, headers: &[(String, String)], body: &[u8], timeout: Duration) -> Result<HttpResponse>; }
pub fn send(cfg: &ProviderConfig, key: Option<&str>, req: &AiRequest, transport: &dyn Transport) -> Result<AiReply>;
```

- **Adapters** (each builds the request and parses the reply; they only differ in shape):
  - Anthropic: Messages API, images as base64 content blocks, the schema as a forced tool (`tool_choice`), the tool
    input is the JSON; `usage` from the reply. Default model `claude-sonnet-5-5`.
  - OpenAI-compatible: chat completions, images as `image_url` data URIs, `response_format` of type `json_schema`;
    covers OpenAI, Grok, OpenRouter, LM Studio via the base URL.
  - Gemini: `generateContent` with `inline_data` parts, `responseMimeType` and `responseSchema`; key in the header.
  - Ollama: `/api/chat` with base64 `images` and `format` = the schema; default `http://localhost:11434`, no key.
- **Transport:** `ureq` (blocking, rustls, no OpenSSL), 60 s timeout; a `Transport` trait so the adapters are tested
  without sockets. Keys go in headers, never in URLs or logs; errors never echo the key.
- **Tasks** (`detect.rs`, `sort.rs`): the fixed prompts, the schemas and the validation.
  - Detect schema: either `{ "kind": "grid", x, y, width, height, rows, columns, gap_x_mm, gap_y_mm }` or
    `{ "kind": "rects", rects: [{ x, y, width, height, angle_deg }] }`, all positions as fractions of the sent image,
    plus a `confidence`. Validation: finite numbers, inside the page, each side at least 15 mm, rows and columns 1 to
    30, at most 200 rectangles, angles within ±45°. The result becomes a `Proposal` with engine `ai` and a confidence
    of **at most 0.8** (so it never reads as exact), whatever the model says.
  - Sort schema: `{ pages: [{ index, label, confidence }] }`, labels from a fixed set; every index must be present once
    and in range. Pages go in batches of at most 20 thumbnails of about 320 px, so 50 pages is three requests.
  - Text-only: Sort sends, per page, its size, object counts (images, paths, text) and the first 400 characters of its
    text; Detect sends the page size and the box of every image and rectangle object (the list the local engine
    reads) and says so in the notice. A page with no objects and no text (a scan) cannot be detected text-only: the
    message says to turn on "Send page images".
- **Estimate** (`estimate.rs`): input tokens ≈ per image `width × height / 750`, plus text and the prompt; output budget
  from the schema; requests from the batching. Dollars only for the default models in a small table marked "list
  prices, 2026-10, approximate"; otherwise tokens only.

### Tauri side (`src-tauri/src/commands/ai.rs`)

- Commands: `ai_set_enabled`, `ai_key_status(provider)`, `ai_set_key(provider, key)`, `ai_delete_key(provider)`,
  `ai_test_connection(config)`, `ai_estimate(task, document, pages, config)`, `ai_detect_pieces(document, page,
  config)`, `ai_sort_pages(document, config)`. There is **no command that returns a key**: once typed, it lives in the
  keychain and is read only inside Rust when a request is sent.
- **Keychain:** the `keyring` crate called from Rust (macOS Keychain, Windows Credential Manager, the Secret Service on
  Linux), service `gutterberg-ai`, one entry per provider. Not a webview plugin, so the key never sits in JavaScript
  after the field is submitted. If there is no keychain (a Linux session without a Secret Service), saving fails with
  `ai_keychain` and AI Mode cannot be used: there is no file or preference fallback.
- Page images come from the render worker (`Work::AiImages`: PNG of the requested pages at a long side, a 4.5 MB cap
  per image by shrinking until it fits). Provider calls run in `spawn_blocking`; one AI action at a time.
- Capabilities and CSP are unchanged.

### Frontend

- Preferences version 8: `ai { enabled: false, provider: "anthropic", sendImages: true, providers: { <kind>: { model,
  baseUrl } } }`. No key, ever. "Reset to defaults" turns AI Mode off and clears models and URLs but leaves the
  keychain alone (the Remove button does that).
- `lib/ai-api.ts` (Zod for replies), `lib/ai-actions.ts` (confirm → call → draft), `ai-store` (session: running, the
  confirm request, the last usage, the sort proposal), `components/ai/*` (settings section, confirm dialog, sort list),
  an engine choice added to `DetectSection`, `layout-store.applySkips(pages, skipped)` (one `set`, one undo step).
- Strings in both catalogs (glossary: "piece", "sheet"; new: **AI Mode / Modo IA**, **proposal / propuesta** as in M17).
  Rust errors reach the UI as codes: `ai_disabled`, `ai_no_key`, `ai_keychain`, `ai_http`, `ai_timeout`, `ai_refused`,
  `ai_invalid_reply`, `ai_invalid_proposal`, `ai_text_only_needs_objects`.

## Settings and defaults

| Setting | Default |
| --- | --- |
| `ai.enabled` | off |
| `ai.provider` | Anthropic |
| model | `claude-sonnet-5-5` for Anthropic; empty for the others (free text, with an example under the field) |
| base URL | empty (provider's own); Ollama `http://localhost:11434` |
| `ai.sendImages` | on |
| Detect image size | 1000 px long side |
| Sort thumbnails | 320 px long side, 20 per request |
| AI proposal confidence | at most 0.8 |
| timeout | 60 s |

## Tests

Rust (`crates/card-ai/tests`, no real API and no real keychain):

- Each adapter builds the documented request (URL, headers with the key, body with images and schema) and parses a
  recorded reply of the documented shape, including usage; error bodies (401, 429, 5xx) and refusals map to codes.
- Validation: bad JSON, missing fields, numbers out of range, rectangles outside the page, too many pieces, rows and
  columns beyond 30, unknown labels, a missing or repeated page index.
- A tiny local HTTP server checks the real transport (headers, body, timeout when the server sleeps, redirect refused).
- **Off means off:** with `ai_enabled` false every command fails with `ai_disabled` and the listener sees no connection.
- Keychain through `keyring`'s mock store: set, status, replace, delete; a failing store gives `ai_keychain`; a test
  scans the logged and returned error text for the key.
- Estimate arithmetic and batching (50 pages → 3 requests); text-only requests contain no image part.

Frontend (Vitest): preferences v8 (migration from 7, defaults, reset turns it off); with AI Mode off a rendered
Source and Print tab contain no AI control (a test walks the DOM for the `data-ai` marker and the words); the section,
the confirm dialog's content (provider, host, page range, text-only line, estimate, session-only checkbox), Detect with
the AI engine gives the usual draft with the "from AI" word, Sort pages review (labels editable, defaults, Apply is one
undo step and only touches skip states, Cancel changes nothing), every error code leaves the project unchanged, locale
parity.

Then `pnpm lint`, `pnpm typecheck`, `pnpm test`, `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`,
`cargo test --workspace` (with `PDFIUM_LIB_PATH`). README: M19 ticked and an "As built" section here.

## Out of scope

- A chat, streaming, follow-up questions, or any request the user did not trigger with a button.
- **Pair fronts and backs** (the outline's "later" button).
- OAuth or account login, usage dashboards, a price lookup over the network, saving AI results or prompts in the
  project, caching replies.
- A fallback for keys without a keychain (no environment variable, no file).
- Training or sending anything beyond the pages the notice names.
- Sending whole-PDF text or pages the user did not include.

## Decisions (approved by the owner)

1. All network traffic is in Rust, in a new `card-ai` crate, with `ureq`; the webview keeps no network access.
2. The key is stored with the `keyring` crate (not a Tauri plugin) and can only be written, tested and deleted from the
   UI, never read back. Linux needs a Secret Service (Linux builds may need `libdbus-1-dev`, added to CI).
3. The **AI Mode** entry in Preferences is the one thing visible while the mode is off.
4. The AI path is not a `Detector` of M17 (those run offline on `PageData`); it returns the same `Proposal`, with engine
   `ai` and confidence capped at 0.8.
5. Sort pages pre-fills Skip for rules, cover and other, keeps cards and backs.
6. All four providers are written from the providers' documented formats and tested against recorded replies and a
   local test server; **none has been tried against a live API** until you run it with a real key.
7. Every AI action asks for confirmation; only single-page Detect can be silenced, for the session.
8. Costs are shown in tokens always, in dollars only for the default models, labelled approximate.

## As built

Where the implementation settled on details the plan left open, or went another way:

- **Crates.** `crates/card-ai` (no Tauri, no UI; depends on `card-core` for `Proposal`/`Detection` and geometry) is the only
  crate that talks to the network. Modules: `provider` (the one request shape, `send`, the base-URL rules), `adapters`
  (Anthropic, OpenAI-compatible, Gemini, Ollama), `tasks` (Detect prompt, schema, validation), `sort`, `estimate`,
  `gate` (the on/off switch and `guarded_send`), `keystore` (the `KeyStore` trait and an in-memory store), `run`
  (`Runner`: gate, page, key, send, validate), `transport` (`ureq` 3 with rustls: 60 s, no redirects, error statuses
  returned as answers). `card-core` grew only the inputs the requests need: `RenderWorker::page_objects`,
  `page_summaries` and `render_fit` (a PNG with a given long side, shrunk until it fits a byte limit), and
  `detect::read::{read_objects, read_summary}` beside `read_page_data`.
- **The switch.** `AppState.ai_gate` (a `card_ai::Gate`) is set by `ai_set_enabled`; every other command, and
  `Runner` itself, checks it before the keychain is read or anything is sent. The interface re-sends the preference
  before each AI call (`syncAiGate`) and whenever it changes, so Rust's switch is never stale after a restart. A test
  counts connections to a local listener: none while off.
- **Keychain.** `src-tauri/src/keychain.rs`, the `keyring` crate (macOS Keychain, Windows Credential Manager, the Linux
  Secret Service through `sync-secret-service` with `crypto-rust`), service `gutterberg-ai`, one cached entry per
  provider. `KeyStore` has `get`, `set` and `delete`, but the commands expose only `ai_key_status` (a yes/no),
  `ai_set_key` and `ai_delete_key`; the key is read inside Rust when a request is sent and nowhere else. A keychain
  that fails is `ai_keychain` and AI Mode simply cannot send; there is no fallback. Linux builds need `libdbus-1-dev`
  (added to CI) and a running Secret Service at run time. `ai_set_key` needs AI Mode on; `ai_delete_key` works while
  it is off, so a key can always be removed.
- **Providers.** Anthropic: Messages API with the schema as a forced tool, images as base64 blocks, `x-api-key`. OpenAI
  -compatible: chat completions, `image_url` data URIs, strict `json_schema`, bearer key, any base URL; no output
  limit is sent (OpenAI and compatible servers disagree about `max_tokens` and `max_completion_tokens`). Gemini:
  `generateContent` with `inline_data`, the key in `x-goog-api-key` (never the URL), the schema converted to Gemini's
  dialect (capital type names, no `additionalProperties`). Ollama: `/api/chat`, base64 `images`, the schema as
  `format`, temperature 0. Replies are read for text refusals, blocked answers and cut-off answers as well as
  statuses; a code fence round the JSON is tolerated. A key is also removed from any provider message that echoes it.
  Plain `http://` is accepted only for `localhost`, loopback and private-network addresses; anything else must be https.
- **Schemas** are flat (no unions, no nulls: `kind` plus fields that are 0 when unused), which every provider takes.
  Detect's reply is validated into a `Proposal` of engine `ai`: inside the page, pieces of at least 15 mm, 1 to 30 rows
  and columns, at most 200 rectangles, tilt normalized to within 45° (a quarter turn swaps the sides). Confidence is
  clamped to 0.35 to 0.8: it never reads as exact, and a model that doubts is still offered, as low confidence.
  Sort's reply must label every page asked about exactly once, from 20 pages per request (so 50 pages are 3
  requests); one bad batch fails the whole run, and no partial labels are kept.
- **Text only.** Detect sends the page size and the boxes of its images, rectangles and lines (largest first, at most
  300) and a page with no objects is `ai_text_only_needs_objects` before the keychain is touched; Sort sends each
  page's size, object counts and the first 400 characters of its text.
- **Not a `Detector`.** M17 said the AI engine would implement `Detector`; those run offline on `PageData` inside
  `detect_page`, so the AI path is a separate command that returns the same `Detection`. `default_engines()` never
  includes it.
- **Preferences version 8.** `ai { enabled, provider, sendImages, providers: { <kind>: { model, baseUrl } } }`, normalized in
  `lib/ai.ts`; a key is not part of it (a test checks no key reaches the stored text). "Reset to defaults" turns AI
  Mode off and clears the models and addresses; the keychain is only touched by "Remove key".
- **UI.** Preferences gets one section, **AI Mode** (`AiSettings`): with the switch off it is the switch and one
  sentence. On, it has the provider, model, address (OpenAI-compatible and Ollama), the write-only key field with
  "saved" status, Replace and Remove, the "Send page images" choice, and Test connection. Elsewhere every AI control is
  rendered only when AI Mode is on and carries `data-ai` (the Detect section's engine choice, the **Sort pages**
  section, the confirm dialog, the usage line). `AiConfirmDialog` is the notice every action stops at (provider,
  server, pages as pictures or text, requests, tokens, cost when known) with Send and Cancel; only single-page
  Detect has "Don't ask again until I close the app". Detect with AI gives the M17 draft ("from AI", never "Exact").
  Sort pages shows a review list (thumbnail, label dropdown, Skip checkbox) and **Apply** sets those skip states in
  one undo step (`layout-store.applySkips`), nothing else. Errors and usage belong to the action that made them.
- **Costs.** Tokens always (pictures at width × height / 750, text a quarter of its characters; outputs half the
  allowance); dollars only for `claude-sonnet-5-5` (3 / 15 dollars per million tokens, list, approximate). The
  estimate is computed from the very requests a run would send, so the pages are rendered for it; afterwards the
  providers' own usage numbers are shown.
- **Tests.** `crates/card-ai/tests/ai.rs` (24: each adapter's request and recorded-shape replies, errors, refusals, the
  address rules, Detect and Sort validation, batching, estimates, a local HTTP server for the real transport including
  timeout, refused redirect and the "off means no connection" check) and `run.rs` (9: order of checks, whole-run
  failure, no key in any error); `src-tauri` keychain tests on `keyring`'s mock store; frontend `ai.test.ts`,
  `ai-actions.test.ts` and `components/ai/ai.test.tsx` (with AI Mode off the sidebar, dialogs and bars contain no `data-ai`
  element and no "AI" text; the settings, key handling, the notice, the Sort review, Detect with AI).
- **Not done / limits.** None of the four adapters was tried against a live provider: they follow the providers'
  documented formats and are tested against replies of those shapes and a local test server, so the first real run
  (Preferences › AI Mode › Test connection) is the real check. Model names are free text and not checked against the
  provider's list. The Linux keychain needs a Secret Service. No "pair fronts and backs", no retry, no caching, and a
  run cannot be cancelled once sent (the request has a 60 s timeout).
