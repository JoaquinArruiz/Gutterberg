# M20 — Hint system: a catalog of help tips, with steps and anchored tours

**Goal:** every help tip lives in one catalog file, any component shows one with
`<HintToast hint="…" />`, and a tip can be a single message or a short tour whose steps sit
next to the part of the screen they explain and advance when the user does the step.

Do this right after M13. Part A (catalog, single tips, stepper) comes first; Part B
(anchored tours with React Joyride) builds on it in the same milestone, or as a follow-up
session if Part A runs long.

**Principles:** few hints, at the moment of need. Hidden gestures and confusing concepts
get a hint; visible, labelled controls don't. Tours are 3–5 steps, always skippable, and
start when the user first reaches the feature, never as a long tour at first launch.

  `prefs.help.dismissedHints`; "Reset help tips" in Preferences clears them
  (`resetHints`); `useHint(id)` in `preferences-store.ts`.

- Both call sites use the same id, `live-preview-manual`, with different text, so closing

## Part A — catalog, single tips, stepper

- **Catalog** (`src/lib/hints.ts`, TypeScript, not JSON):
  ```ts
  type HintStep = {
    title?: string;
    text: string;
    action?: { label: string; run: HintActionId };
    target?: HintTargetId;      // Part B: element to point at (data-hint-target)
    advanceOn?: HintEventId;    // Part B: app event that moves to the next step
  };
  type HintDef = { steps: readonly [HintStep, ...HintStep[]]; version?: number };
  export const HINTS = { ... } as const satisfies Record<string, HintDef>;
  export type HintId = keyof typeof HINTS;
  ```
  - Ids come from the catalog keys; remove the separate `HINT_IDS` list (derive it from
    `Object.keys(HINTS)` for preference validation).
  - Text is plain strings, no JSX, so it can be translated later.
  - A unit test checks every hint has at least one step and no empty text.
- **Actions as names, not functions.** `HintActionId` is a string union (for example
  `"open-preferences:preview"`, `"go-to-stage:print"`). A small registry
  (`src/lib/hint-actions.ts`) maps each name to what it does, so the catalog stays pure data.
- **Component:** `<HintToast hint="live-preview-output" className="…" />`. The call site
  decides *when* (it renders the component only in the right situation) and *where*
  (`className` for position, as today); the catalog decides *what*. Keep the current look
  (`role="status"`, the info icon, the close button, `data-testid="hint-<id>"`).
- **Steps.** One step: looks exactly like today's toast. Two or more: add "2 / 3", Back and
  Next arrows (Next becomes "Done" on the last step), and small dots. ← / → move between
  steps while the toast has focus; Esc closes. Closing (✕ or Done) dismisses the whole hint,
  as today; "Reset help tips" brings everything back.
- **One at a time.** A tiny hint manager: if several hints want to show, only the first
  (in catalog order) is visible; the next appears after it is dismissed or no longer
  rendered.
- **Version (optional field).** If a hint's `version` is higher than the one stored with
  its dismissal, it shows again. Store dismissals as `{ id: version }` instead of a list
  (preferences migration; old list entries count as version 1).
- **Split the shared id** into `live-preview-output` (Output view) and
  `live-preview-sheets` (Print sheets), moving both texts into the catalog. Migration: if
  `live-preview-manual` was dismissed, mark both new ids dismissed.
- **First stepped hint:** `print-stage-intro`, shown the first time the Print stage opens:
  (1) pick cards in the library, (2) set copies, or keep "All cards in order",
  (3) adjust the sheet and page in the inspector, (4) export. Text only in Part A; Part B
  adds targets.
- Update the comment at the top of `hints.ts` to explain how to add a hint.

## Part B — anchored tours (React Joyride)

- **Library:** [React Joyride](https://github.com/gilbarbara/react-joyride) (MIT; supports
  React 19). Add it with `pnpm add react-joyride`. Not Shepherd.js or Intro.js: both are
  AGPL with paid commercial licenses, which conflicts with the owner's possible commercial
  licensing. (Fallback if Joyride doesn't fit: driver.js, also MIT.)
- **Rendering:** single-step hints keep using the M20 `HintToast`. A hint whose steps have
  a `target` runs as a Joyride tour in **controlled mode** (`stepIndex` owned by our hint
  manager), with **our own tooltip component** (the HintToast look: title, text, "2 / 4",
  Back / Next, Skip, ✕), so both kinds look the same. Theme the spotlight overlay with the
  app's CSS variables (light and dark).
- **Targets:** elements opt in with `data-hint-target="…"`; `HintTargetId` is a string
  union so a missing target name is a type error. If a target isn't on screen (panel
  hidden, other stage), the step falls back to a centred toast instead of pointing at
  nothing.
- **Advance on app events, not raw clicks.** A small typed event bus
  (`src/lib/hint-events.ts`, `emitHintEvent("selection-created")`) is called from the
  stores where things happen. A step with `advanceOn` moves forward when its event fires,
  however the user did it (mouse, keyboard, typing a value). Steps without `advanceOn`
  advance with Next. Events: `pdf-opened`, `selection-created`, `grid-changed`,
  `stage-changed:print`, `copies-changed`, `export-started` (add more as hints need them).
- **Skip and dismissal:** Skip or ✕ dismisses the whole tour (same storage as Part A);
  finishing it does too.
- **Tests:** component tests drive a tour with fired events (jsdom + Testing Library, as
  the M13 tests do) and check fallbacks when a target is missing.

## Done when

- Both existing tips render from the catalog with their current text, positions and
  "Open Preferences" button, and dismissing one no longer hides the other.
- `print-stage-intro` steps forward and back with the arrows and the keyboard, and stays
  dismissed after a restart until "Reset help tips".
- Two hints wanting to show at once appear one after the other.
- A typo in a hint id is a TypeScript error.
- Preferences migrate: an old `dismissedHints` list keeps those tips dismissed.
- Part B: `first-pdf-tour` points at the page, the grid fields and the stage tabs in turn,
  advances when the selection is drawn, the grid changes and the Print tab opens (also when
  done by keyboard), can be skipped at any step, and falls back gracefully when a target is
  hidden. Tours and single tips look the same in light and dark themes.
