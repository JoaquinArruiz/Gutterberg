# M15 — Rename to Gutterberg, then distribution (outline)

Firm the distribution part up with the owner before starting. The rename (step 0) is
decided and goes first, before any public build exists.

## Step 0 — Rename to Gutterberg

**Why now:** the app's identifier decides where it stores its data. Changing it after a
public release would make installed copies lose their settings, so rename before the first
build anyone downloads.

**New name:** Gutterberg. Description: "Gutterberg turns print-and-play PDFs and card scans
into cut-ready sheets: exact card sizes, clean gutters, and the original artwork untouched."
Short form (GitHub description): "Turn print-and-play PDFs and card scans into cut-ready
print sheets. Exact sizes, gutters, cut marks, duplex. Desktop app (Tauri, Rust, React)."

**Owner does first** (outside the code, can't be done from a session):

- Confirm the name is clear: domains on a registrar (`gutterberg.com`, `gutterberg.app`)
  and trademarks on USPTO, TMview and INPI Argentina (the owner is in Argentina). As of 2026-10-07 nothing named Gutterberg was found,
  but those databases weren't checked directly.
- Rename the GitHub repo to `gutterberg` (Settings › Repository name; GitHub redirects the
  old URL) and set the short description above. Then
  `git remote set-url origin https://github.com/JoaquinArruiz/gutterberg.git` locally.

**The session changes** (every place the old name appears today):

**Done when:** a search for `pdf-card-editor`, `PDF Card Editor` and `pdf_card_editor`

## Distribution

- A `tauri-action` workflow that builds `.msi`, `.dmg` and `.AppImage`/`.deb` on tag push,
  with pdfium bundled for each platform (pinned, as in M8).
- Publish to GitHub Releases; add the Tauri updater plugin.
- **File association:** register `.gtr` in `bundle.fileAssociations` (`tauri.conf.json`,
  name "Gutterberg project", role Editor), so double-clicking a project opens Gutterberg.
  Handle the opened file at startup (command-line argument on Windows and Linux) and
  through the "opened" run event on macOS, then load it with the M14 checks.
  - Declare a unique type ID for the format: `dev.joaquinarruiz.gutterberg.project`
    (macOS UTI, exported, conforming to `public.json`) and the MIME type
    `application/vnd.gutterberg.project+json` (Linux desktop entry). These are declarations
    in the Tauri bundle config only; nothing has to be registered anywhere.
- Signing: macOS notarisation needs an Apple developer account. Decide with the owner
  whether unsigned builds are acceptable first.
  - If builds ship unsigned, the README explains the first-launch warnings: macOS
    (right-click › Open, or System Settings › Privacy & Security › Open Anyway) and Windows
    SmartScreen ("More info" › "Run anyway").
- README: screenshots or a GIF, a short "why", and a download link.

## Before the first public release

- **License or terms of use (owner decides, the session never picks).** Released
  installers need written permission to use the app and a "no warranty, no liability"
  disclaimer. The owner is leaning towards **PolyForm Noncommercial 1.0.0** plus a CLA for
  contributors:
  - If the owner adopts it before the release: add the official license text as
    `LICENSE` (from polyformproject.org, unmodified) with the line
    `Required Notice: Copyright Cac0 (https://github.com/JoaquinArruiz/gutterberg)`, a README
    line "For commercial use, contact joaquinarruiz@gmail.com", show the license from the
    About section, and set up CLA Assistant before accepting outside pull requests.
    PolyForm's own "no liability" clause covers the disclaimer.
  - If the license is still undecided: ship short interim **Terms of use** instead (in the
    installer and the About section): free to use, provided as is with no warranty, no
    liability, all rights reserved by the owner. Replace them once the license is chosen.
  - Until the owner says which, keep following `CLAUDE.md`: no `LICENSE` file.

- **Third-party licenses.** The app ships other people's code (Tauri, React, lopdf,
  pdfium-render, and pdfium with its bundled libraries such as FreeType and libjpeg-turbo).
  Their licenses (MIT, Apache-2.0, BSD) allow this, on condition that their notices ship
  with the app. Generate a `THIRD_PARTY_LICENSES` file in the release workflow (for
  example `cargo about` for the Rust crates and `pnpm licenses list` for the npm packages;
  add pdfium's own `LICENSE` and the notices of the libraries it bundles), include it in
  every installer, and show it from the About section in Preferences.
- **Respect PDF permission flags.** Today the export drops a source PDF's encryption and
  permissions, so a file locked by its publisher comes out unlocked. Replace that with:
  1. The PDF disallows **printing** or **modifying**: refuse before the save dialog, with a
     clear message: "This PDF's publisher doesn't allow changes. Contact them for an
     unlocked print-and-play version." Show it in the M11 pre-flight list.
  2. Other restrictions only (for example "no copying text"): export, and apply the same
     permissions to the output instead of stripping them. If lopdf can't write encryption,
     fall back to refusing with the same message, and note that in this brief.
  3. No restrictions: unchanged.

  Read the flags when the PDF opens, so the UI can say so early (a small lock badge with
  the reason). Add fixtures for each case. Replace the README line about export removing
  encryption with the new behaviour.
