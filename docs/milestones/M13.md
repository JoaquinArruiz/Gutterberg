# M13 — Print stage UI

Note (M21): the UI now says "Source" for the Cards tab and "pieces" for cards, and every text lives in `src/locales/`. This brief is kept as it was written.

**Goal:** pick cards, set quantities and export a ready-to-print PDF from the app.

Examples that must work:

- Print 9 copies of card 1 on one 3×3 page.
- Choose 3 cards and fill one page with them.

## Scope

- **Stage switch** (decided: tabs, not a dialog). A segmented control in `EditorToolbar`:
  Cards | Print. Print swaps the whole window to the card library, sheet preview and print
  settings. Add `stage` to
  `ui-store`. Each stage registers its own panels with the workspace layout system
  (`src/lib/workspace-layout.ts`, `src/components/workspace/`) and remembers its own layout.
- **Card library panel.** A virtualised grid of card thumbnails, each rendered with
  `render_region` at a small width and cached by `CardId` + width. Filter by page or group.
  Click selects a card and shows a quantity stepper (0–99); Shift-click selects a range.
  "Select all" and "Clear".
- **Plan.** "All cards in order" (today's behaviour, the default) or "Custom selection"
  with a quantity per card (e.g. 4 × A, 2 × B, 3 × C). An **Auto-fill** toggle repeats the
  selected cards until the last sheet is full. An **Order** toggle: Grouped (AAAA BB CCC)
  or Interleaved (ABC ABC A C A).
- **Sheet preview.** Pages from `compute_sheets`, drawn with the card crops (same approach
  as `OutputPreview`). Page navigation and an "n sheets, m cards" summary.
- **Inspector.** Move output spacing, page size, orientation and margins here from the
  Cards sidebar, plus the sheet grid (rows × columns, or Auto) and a **Group cards by
  size** toggle (on by default; maps to `group_by_size` in `paginate`).
- **Collapsible inspector sections.** The Print inspector will keep growing (cut marks,
  bleed and duplex in M16; real size and turn in M18), so build it from collapsible
  sections from the start: **Plan**, **Sheet**, **Page** (later **Marks & bleed**,
  **Duplex**). Plan and Sheet are open by default; the app remembers which sections are
  open (a per-viewer preference, like the panel layout). Use the same section component in
  the Cards sidebar.
- **Export** from the Print stage calls `export_sheets`, with the M11 pre-flight.

## Done when

- Both examples above work end to end, plus 4 × A, 2 × B, 3 × C in both orders.
- With mixed card sizes, the toggle switches between separate sheets per size and one
  shared grid.
- "All cards in order" exports the same file as before this milestone.
- Inspector sections collapse and expand, and their state survives a restart.

## As built

Where the implementation settled on details the brief left open:

- **Stage switch.** `ui-store.stage` (`cards` | `print`), tabs in `EditorToolbar`. The page
  editor's tools, zoom and Source/Output/Split views are shown in the Cards stage only; the
  single-key shortcuts are off in the Print stage. Undo/redo stay in both (they also cover the
  output settings).
- **Per-stage layout, simplified.** The Print stage has its own fixed three-panel layout (card
  library, sheets, inspector) with remembered widths (`prefs.print.layout`, honouring "remember
  sizes"). It does not go through the Cards stage's panel registry (`workspace-layout.ts`);
  moving panels between regions in the Print stage is not built. (M22 did it: the Print tab's piece library and settings are panels of a layout of their own, in the same registry.)
- **Card library** (`CardLibrary`, `CardThumb`). Cards come from `compute_cards`
  (`extract_cards`). A windowed grid (`lib/virtual-grid.ts`) mounts only the rows in view.
  Thumbnails are `render_region` crops, cached by card id + crop geometry + width bucket
  (`lib/image-cache.ts`, 400 images, least recently used). Filter: all, one grid group, or one
  page. Click selects, Ctrl/Cmd toggles, Shift selects a range; "Select all" and "Clear".
- **Plan.** Default `all`: every card once, in order, nothing to choose. Changing a card's copies
  switches to `custom` (starting empty: only cards with copies print); "Start from all cards" seeds
  one of each. Copies are 0 to 99 (`Copies` field and steppers act on the selection). Auto-fill and
  the Grouped / Interleaved order are in the Plan section.
- **Sheet grid.** Three choices in the Sheet section: *Same as source* (default; only for all
  cards in order without auto-fill), *Auto* (as many as fit), *Rows × columns*. "Same as source" is
  `PrintLayout::SameAsSource`: each grid page becomes one sheet through the very same
  `calculate_layout`, and a test shows it is byte-identical to the Cards-stage export, which meets
  "all cards in order exports the same file as before".
- **Rust additions to the M12 engine** (`crates/card-core/src/sheet.rs`, `export.rs`):
  `PaginateOptions.auto_fill`, `SheetPage::SameAsSource` (resolved from the first printed card's
  page in `plan_sheets`), `PrintLayout`, `source_sheets`, `plan_print`, `sheet_from_layout`
  (shared with `export_document`), `layout::calculate_fitting_layout`, `export::validate_sheets`,
  `plan_print_file`, `export_sheets_file`, `page_sizes`.
- **Commands.** `compute_cards`, `compute_sheets` (now takes a `PrintLayout`), `validate_print`
  and `export_print`. Preview and export run the same planner; the export reads page sizes from the
  file, the preview uses the sizes the UI has. A shared JSON fixture
  (`crates/card-core/tests/data/print_request.json`) is produced by the frontend's request builder
  and consumed by a Rust test, so the two cannot drift apart.
- **Export.** The toolbar's Export button follows the stage. Print: `validate_print` (page problems,
  or the plan's own error such as cards that do not fit) before the save dialog, then `export_print`.
  Cards: unchanged (`validate_export` + `export_document`).
- **Inspector.** Output spacing, page size, orientation and margins moved from the Cards sidebar
  into the Print inspector (`print.sheet` has the spacing, `print.page` the page and margins). The
  Cards sidebar keeps a short "Output" section that opens the Print stage. `CollapsibleSection` is
  used by both inspectors; open/closed state is `prefs.inspector.sections` (Plan and Sheet open by
  default, Page folded). Preferences version 4.
- **Sheet previews strip.** A row of small sheet previews sits under the "Sheet 1 of N" bar
  (`SheetStrip`), like the page thumbnails of the Cards stage. The arrow at the left of the bar hides
  and shows it; the choice is remembered (`prefs.inspector.sections["print.sheet-strip"]`). The
  large sheet in front is always live: it is redrawn whenever the plan changes (copies, order, grid,
  spacing...) and when another sheet is chosen, and "Sheet i of N" and the summary come from the
  current plan. Only the row of previews obeys Live Preview: on, it tracks the plan; off, it shows the
  sheets as of the last refresh (`print-store.sheetsSnapshot`), with the "live preview" help tip, a
  "Previews out of date" mark and a refresh button in the bar (the same `RefreshButton`); none of
  these show while the row is hidden. Entering the Print stage starts a fresh plan (`beginPlanning`),
  and the first plan is shown in the row without a click. Export always uses the live plan.
- **Limits.** (Both lifted by M18.) Card images for sources that are rotated (M18) show their bounding box, not
  straightened. Sheet thumbnails and drag-to-sort are not built (M18 sorts the library).
- **Tests.** `sheets.rs` covers the plan-level examples; the component tests
  (`print-stage.test.tsx`, jsdom + Testing Library) cover the library, the preview, the inspector and
  the stage switch. The Tauri window itself was not driven by hand while writing this.
