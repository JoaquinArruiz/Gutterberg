# 0.17.0 — Export from the command line

When a publisher updates a print-and-play PDF, the pieces are usually in the same places. Re-exporting a saved
project without opening the app makes that one command, and lets people script it.

## Goal

```sh
gutterberg export my-game.gtr -o my-game-sheets.pdf
gutterberg check my-game.gtr        # says what an export would refuse, writes nothing
```

The output is the same file the app's Export writes for that project.

## The work that matters: the print request moves into `card-core`

Today the UI turns its stores into the request the engine takes (`buildPrintRequest`, `toRustGroups` and the card
edits in `src/lib/print-request.ts`). The `.gtr` file holds the UI's shape (`project.rs`: "everything after those two
keys belongs to the UI"). A command line cannot run that TypeScript, so:

1. Move the step from a project body to a `PrintRequest` into `card-core` (a typed reading of the project's page
   groups, freeform pieces, edits, plan and output settings), with tests that compare it against what
   `print-request.ts` builds for the same projects (use the example projects and a few made for the tests).
2. Have the app use it too, so there is one source of truth, as `AGENTS.md` asks for geometry. The UI keeps building
   requests from its live stores while editing; check whether it can send its stores in the project shape and let
   Rust build the request, and do that if it does not slow down the live preview.

## Steps

1. The move above.
2. **The command.** Settle with me: a subcommand of the app's own binary (no second file to install; on
   Windows the app is a GUI program, so printing to the terminal needs attaching to the parent console) or a separate
   small binary in the installers. Arguments: the project, `-o` for the output, `--force` to export even when a PDF's
   hash changed (otherwise it stops and says which PDF changed, as the app asks).
3. **What it needs.** Export uses `lopdf`, not pdfium; check that the command line needs no pdfium at all, including
   for projects with image pieces.
4. **Messages** in English (the command line has no language preference), the same error codes as the app.
5. **Tests**: export a test project from the command line and compare with an export from `card-core` directly.
6. **Docs**: a section in `README.md`, `docs/architecture.md`; **changelog**.

## Out of scope

- Changing settings from the command line (sheet size, gaps…): open the project in the app for that.
- Detect pieces or AI Mode from the command line.

## Done when

`gutterberg export` writes the same PDF as the app for every example project; a changed PDF stops it unless
`--force`; every check in `AGENTS.md` passes.
