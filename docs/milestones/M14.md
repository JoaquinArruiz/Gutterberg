# M14 — Project files, several PDFs and presets

**Goal:** work survives a restart, and one project can take cards from several PDFs.

## Scope

- **Project file: `.gtr`**, a JSON file holding: each source PDF's path, `document_id` and
  content hash, the document layout (groups, grids, freeform cards), the print plan
  (selection, quantities, order, turns) and the output settings. It does not embed the
  PDFs.
  - **Signature first.** The file starts with
    `{ "format": "gutterberg-project", "version": 1, ... }` (write these two keys first).
    This is the file's "magic number" while it stays valid, human-readable JSON.
  - **Checked on open, in Rust**, before anything else, with three clear outcomes:
    1. Not JSON, or `format` missing or different: "This is not a valid Gutterberg
       project file."
    2. Older `version`: migrate silently (versioned migrations, like preferences in
       `src/lib/preferences.ts`).
    3. Newer `version`: "This project was made with a newer version of Gutterberg. Please
       update." Never open it partially.
  - Validated with Zod on the frontend as well.
  - **Moved PDFs:** if a source PDF is missing, ask "Where is this file now?" and accept
    the new location if its hash matches (warn if it doesn't).
  - Later, if "Save with PDFs included" is added: switch to a zip container whose first
    entry names the format (like EPUB / ODF). Not part of this milestone.
  - The app is still called "PDF Card Editor" in the code until M15; use the final
    `gutterberg-project` signature and `.gtr` extension now anyway, so files saved before
    the rename stay valid.
- File menu: New, Open project, Save, Save as, and recent projects. Warn when the PDF's
  hash differs from the one saved.
- **Several source PDFs:** "Add PDF" to a project. The Source tab gets a document
  switcher; the piece library shows pieces from every document, filterable by document; the
  Print tab can mix them on one sheet (the M12 engine already supports it).
- **Presets:** save the current grid and spacing under a name ("3×3 poker, 0 mm") and
  apply it to any page group.

## Done when

- Save, quit, reopen: the same layout, plan and output settings are back.
- One sheet holds cards from two different PDFs and exports correctly.
- A preset applied to a page group sets its grid and spacing.
- Migration is tested from a hand-written older project file.
- Opening a non-project file, a renamed PDF, or a file with a higher `version` shows the
  matching message and leaves the current project untouched.

## As built

Where the implementation settled on details the brief left open:

- **The file.** `.gtr`, JSON, indented, `format` and `version` first (Rust writes them; any `format` or
  `version` in the content is replaced). The content is the UI's own model in camelCase with normalized
  coordinates, not the Rust shapes: `documents[]` (`id`, `path`, `hash`, `pageCount`, `groups`, `freeform`
  by page, `viewedPage`), `activeDocument`, `output`, `edits` (`turns`, `scales`, `order`) and `plan`
  (everything in `PrintPlan`, so copies, auto-fill, order, size groups and the sheet grid). Not saved:
  undo history, the picked piece, zoom and tool, hint state (that is a preference). `src/lib/project.ts` has
  the Zod schema, `toProject` / `fromProject` (which pulls out-of-range values back into what the UI allows)
  and `projectSignature`.
- **The format check is Rust's** (`crates/card-core/src/project.rs`, command `open_project`): `parse_project`
  gives `NotAProject` (not JSON, not an object, `format` missing or different, `version` not a whole number
  from 1 up, a file that is not text, or over 64 MiB), migrates an older version one step at a time, or gives
  `ProjectTooNew` (never opened partially). They reach the UI as the codes `not_a_project` and
  `project_too_new`; a file with the right signature but a damaged body is the frontend's `project_invalid`.
  **Migrations:** the table is empty because version 1 is the first; the machinery (`parse_project_with`) is
  tested with a made-up history and a hand-written old file (`tests/data/project_v1_handwritten_old.gtr`), so
  the first real migration only adds a function.
- **Wording.** The messages say "project file" and "the app", not "Gutterberg", because the rename is M15;
  `project.*` and `errors.not_a_project` / `project_too_new` / `project_invalid` in the two catalogs are the
  strings to touch then.
- **Opening is all or nothing.** The file is checked, every PDF is found (and hashed), and only then do the
  stores change. A PDF that is gone: "Where is this file now?", the new place is taken if its hash matches; if
  not, the user is told and chooses to use it anyway or look again; giving up opens nothing. A PDF at its saved
  place whose hash differs: opened, with a notice. A PDF whose page count no longer fits the saved page groups
  (or freeform pieces): that PDF's layout is reset, with its turns, sizes, order and copies, and a notice says so.
  If a PDF cannot be read, the previous ones are opened again in the render thread. A project whose PDF moved
  or whose layout was reset counts as modified, so saving rewrites the file.
- **Several PDFs in the engine.** `RenderWorker` keeps a map of open documents (`open(id, path)`, `close`,
  and the render calls take the id); `AppState` keeps their paths. `sheet::DocumentSource` with
  `extract_all_cards`, `plan_sheets_in`, `source_sheets_in` and `plan_print_in` plan over several documents
  (the single-document functions are wrappers); `export::plan_print_files` / `export_sheets_files` /
  `validate_sheets_in` do the same from files. `PageIssue` carries `document_id`. The commands take
  `documents: [{ document_id, pages?, groups }]` (the shared JSON fixtures changed to that shape), and
  `export_document` / `validate_export` (the Source tab) take the id of the PDF being edited. Document ids
  are the ones cards carry; the first PDF of a project is 0 and added ones take the next free number.
- **Several PDFs in the UI.** The layout store holds the layout of the PDF being edited (`groups`,
  `freeform`) and `parked` layouts of the others; switching swaps them (`switchDocument`), so every edit,
  drag and undo step still works on one PDF. Undo history is cleared when a PDF is opened or switched. Turns,
  sizes and order stay project-wide (their keys carry the document, and deleting a freeform piece renumbers
  only its own PDF's). `useLayoutDocuments()` is the list the Print tab plans from. The page panel has the
  PDF dropdown (with two or more) and "Add PDF…"; the library filter lists "All pieces of X" and groups named
  after their PDF once there are several; piece images are cut from the PDF the piece belongs to.
- **File menu and tracking.** `FileMenu` (toolbar): New project, Open PDF (a new project from one PDF; the
  output settings carry over as before), Open project, Add PDF, Save, Save as, recent projects (8, in
  preferences v7 `files.recent`; one that is gone is forgotten). `Ctrl/Cmd+N`, `O`, `Shift+O`, `S`, `Shift+S`.
  The status bar shows the project's name and a dot while it has unsaved changes (`useProjectTracking`
  compares the signature after 150 ms; turning pages does not count). Replacing a modified project asks first
  (native dialog; permission `dialog:allow-ask`). Messages and errors from these actions show under the toolbar
  (`ProjectNotices`), so a failed open never covers the project that is still there.
- **Presets** are the viewed group's rows, columns and source gap under a name, in preferences v7 `presets`
  (up to 50, names up to 60 characters, a repeated name replaces). They belong to the user, so "Reset to
  defaults" keeps them and the recent projects. Applying sets them on the viewed page's group; go to another
  group and apply again. The output gap is global, not per group, so it is not part of a preset.
- **Tests.** Rust: `tests/project.rs` (the three outcomes, odd inputs, migrations, the written envelope, the
  hash), `tests/documents.rs` (cards of two documents on one sheet, order across documents, same-as-source,
  duplicate ids, export from two files, issues naming the document), `tests/documents_render.rs` (a sheet with
  a piece from each of two different PDFs, rendered with pdfium), and the worker test with two documents.
  Frontend: `project.test.ts` (schema, round trip, clamping, signature), `project-actions.test.ts` (new, open,
  save, relink, hash mismatch, page count mismatch, not a project, too new, damaged, recents, several PDFs,
  switching), `components/project.test.tsx` (library, filter, sheet, switcher, File menu, notices, presets),
  plus the preferences v7 and library-filter cases.
- **Not done / limits.** No way to remove a PDF from a project. No prompt when the window is closed with
  unsaved changes. No "Save with PDFs included" (the zip container) and no file association (M15). Not
  driven by hand in the Tauri window while writing this: the dialogs (`ask`, open, save) and the File menu
  are only covered through mocks and jsdom.
